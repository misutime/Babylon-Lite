# 模块：屏幕空间环境光遮蔽（Screen-Space Ambient Occlusion）

> 入口点：`packages/babylon-lite/src/post-process/ssao.ts`。
> 支持模块：`packages/babylon-lite/src/post-process/ssao/`。

## 用途

提供一个按需启用的 WebGPU AO 缓冲区，根据透视或正交相机的深度附件与可选的有符号表面法线计算，默认启用空间和时间重建。XeGTAO 是唯一的估算器。现有场景的渲染、黄金图和体积上限保持原样。

`createSsaoTask` 构建完整的生产管线。重建并非调用方必须手动开启的第二个特性：低/中档空间采样和 Half 分辨率渲染都依赖它来达到可用的噪点水平。显式的纯空间模式仍保留用于诊断或供其他消费方滤波器使用。

正交相机沿用 Full/Half 管线，支持重建法线、时间历史、物体运动传输及可选的运动裁剪。对反向 Z 投影的 `P10` 和 `P14`，正交路径用 `(deviceDepth - P14) / P10` 解包视图深度，透视路径仍用 `P14 / (deviceDepth - P10)`。正交视图的 XY 为 `uv * ndcMul + ndcAdd`，其中 `ndcAdd` 包含偏心平移 `(-P12/P0, -P13/P5)`。视线方向平行，均为 `(0,0,-1)`，投影半径和像素覆盖范围与视图深度无关。Uniform 仍为 176 字节，`extra.x` 选择正交计算，`extra.y` 保留强度，其余两个分量保留。共享深度转换函数也处理向量形式的法线重建输入，以及上一帧视图深度到设备深度的逆转换。时间重建的静态深度系数取自 `previousView * inverse(currentVP)` 的第 2 行（从 0 开始），因为正交相机上一帧的裁剪空间 W 恒为 1。投影模式、缩放或偏心参数变化后，先使历史失效，再复用重投影状态。

显式正交边界可以采用与渲染目标不同的宽高比。`aoProjectedRadius(radius,z)` 分别沿两个轴返回 `radius / (aoViewScale(z) * abs(ao.pixelViewSize))`。估算器的切片方向在视图空间保持为 `(cos(phi),sin(phi),0)`，像素偏移为 `(cos(phi),-sin(phi)) * projectedRadius`，最小步长为 `1.3 / length(pixelOffset)`。小覆盖范围的可见性偏差以投影长轴为基准。传输阶段也搜索椭圆，使用投影长轴作为运动裁剪的保守边界以及返回的物理半径边界。256 像素的搜索上限按相同比例缩放两条轴，保持椭圆宽高比。每个接收体的投影缩放只在进入采样循环前计算一次。

正交路径仅在导入 `enableOrthographicCamera` 时进入产物。调用方读取相机模块已有的可空 `_orthoProjector` 接口，使仅用透视的产物可以剔除正交 CPU 分支和着色器表达式。着色器工厂在相机配置完成后，选择原有的共享透视常量或按需生成的支持正交的常量。GPU 资源所有者记录这项能力。首帧之后启用正交相机时，会一次性替换原先仅支持透视的资源所有者及其 Half 适配器和时间历史。调用方沿用现有 SSAO 启用器和公开相机 API。

各 Pass 专用的 PBR 插件片段保留原始材质签名的片段 ID，即使该 Pass 只选取部分插件。插件选择为空时，只提供 ID 的片段也能满足 Alpha 测试的依赖，同时让几何和阴影 Pass 避免采样 AO。两种别名均在注册不可变 Pass 签名时创建一次，供后续着色器组装复用。

`depthTexture` 直接借用单采样**深度附件**，包括来自 `createGeometryRendererTask` 的 `geometry.geometryDepthTexture` 或现有渲染目标的深度附件。它不需要诸如 `geometryViewDepthTexture` 的深度值颜色 MRT，也不会创建第二个当前设备深度附件。生产 Pass 必须存储其深度并在 AO 之前运行；多重采样附件需先经过现有的深度解析（depth-resolve）任务。AO 仅为借用附件创建一个仅深度采样视图，绝不销毁生产者的纹理。其自有的线性/视图深度 mip 金字塔、卷积深度与上一帧几何历史仍作为独立算法资源存在：借用输入省去的是重复的源深度存储，而非每一次深度读取、转换或时间历史开销。

实现路径在进入场景光照合成前先达成数值级 GPU 缓冲区对等。AO 任务不会直接与最终场景图像相乘：这样做会错误地压暗直接光与自发光材质。AO 缓冲区任务独立校验。PBR 光照单独启用；仅导入或添加该任务本身不会改变任何材质的光照。

## 算法标识与来源

`createSsaoTask` 管线使用单一 AO 估算器：XeGTAO，基于 [Intel 的实现](https://github.com/GameTechDev/XeGTAO/tree/a5b1686c7ea37788eeb3576b5be47f7c03db532c)。此处描述的默认时间累积、卷积、历史修复和空间重建改编自 [DiligentFX 的 AO 重建](https://github.com/DiligentGraphics/DiligentFX/tree/eaf6ab785968bdee2393210c5a67033a4d9140cc)。它们用于过滤 XeGTAO 输出；不存在独立的运行时“Diligent”AO 实现或算法选择器。这一组合并不冒充为 Intel 未经修改的完整管线。

在 `master` 上添加的独立 `createScreenSpaceAmbientOcclusionPostProcessTask` API 仍然可用，详见[模块 52](52-screen-space-effects.md)。它独立于此 XeGTAO 任务及其仅限漫反射的 PBR 集成。

当希望可见性仅影响 **PBR 漫反射 IBL** 时，选择 `createSsaoTask`：

```ts
const ao = createSsaoTask({ depthTexture, normalTexture, camera }, engine, scene);
await enablePbrSsao(scene, ao);
```

将深度/法线生产者调度在 `ao` 之前，并将消费它的 PBR Pass 调度在它之后。当期望效果为**最终颜色相乘**（包含源中的直接光/高光/自发光贡献）时，选择独立的后处理 API：

```ts
const ao = createScreenSpaceAmbientOcclusionPostProcessTask({ sourceTexture: litColor, depthTexture, camera, composition: "multiply" }, engine, scene);
```

将该任务调度在源颜色/深度生产者之后。这两者是互斥替代方案，而非针对同一 AO 叠加的两个阶段：后处理 `occlusionTexture.r` 存储遮蔽量，而 XeGTAO 的 `outputTexture.r` 存储可见性。切勿将一个 API 的输出/设置传递给另一个 API 的启用器。

运行时模块、内部符号与 GPU 标签使用 `xegtao`。上游许可证保留 DiligentFX 名称以标识实际源实现。XeGTAO 的 MIT 许可证与 DiligentFX 的 Apache-2.0 许可证（在固定提交处无随附 NOTICE 文件）保存在 `packages/babylon-lite/third-party-notices/` 下，并包含在发布包生成的 `NOTICE.txt` 中。改编的重建模块（`ssao-xegtao-wgsl.ts`、`ssao-xegtao-gpu.ts`）中注明它们改编自 DiligentFX。

## 公共 API 接口

```ts
type SsaoQuality = "low" | "medium" | "high" | "ultra";

interface SsaoTaskConfig {
    name?: string;
    depthTexture: RenderTarget;
    normalTexture?: RenderTarget;
    normalSpace?: "view" | "world";
    camera: Camera;
    quality?: SsaoQuality;
    radius?: number;
    intensity?: number;
    temporal?: boolean | SsaoTemporalOptions;
}

interface SsaoTask extends Task {
    readonly depthTexture: RenderTarget;
    normalTexture: RenderTarget | null;
    readonly camera: Camera;
    readonly outputTexture: RenderTarget;
    enabled: boolean;
    quality: SsaoQuality;
    radius: number;
    intensity: number;
    readonly temporal: SsaoTemporalSettings;
}

function createSsaoTask(config: SsaoTaskConfig, engine: EngineContext, scene?: SceneContext): SsaoTask;
function enablePbrSsao(scene: SceneContext, task: SsaoTask, materials?: readonly PbrMaterialProps[]): Promise<void>;
```

所有字段均为纯状态。基础架构的 `Task` 生命周期与现有帧图任务一致。公共配置不暴露任何原始 GPU 句柄。在创建深度/几何目标之后调用，并将任务添加在其生产任务之后、AO 目标消费方之前。输出采用可见性语义：白色表示无遮蔽；黑色表示被遮蔽。它是一个可过滤的 `rgba16float` 渲染目标。

默认值：半径 0.5 视图单位、强度 1、启用、且启用时间重建。`temporal: false` 显式选择纯空间输出；`temporal: { enabled: false, ...options }` 也可在以禁用状态启动前配置其未来的速度输入。`ao.temporal` 是指向可变纯设置的一个稳定只读引用。可在运行时修改 `ao.temporal.enabled` 或 `ao.temporal.historySamples`；镜头切换时使用 `resetSsaoTemporal(ao.temporal)`。配置的速度源/深度契约在构造时捕获，不会因修改原配置对象而改变。

初始禁用时不会分配或执行任何时间 GPU 历史或时间所有者 Pass。控制器及其少量 CPU 状态仍保留，以便后续显式实时重新启用。因此，`temporal: false` 是运行时禁用，而非承诺将重建代码从打包中 tree-shake 剔除。完全不使用整个 SSAO 特性才会将其 tree-shake 剔除；选择纯空间输出仍会保留支持 `ao.temporal.enabled = true` 所需的代码。浮动原点重投影不受支持：在该环境下默认启用的构造会显式失败，且重新启用先前禁用的控制器在分配时间 GPU 资源前也会失败。在该环境下使用纯空间模式需要显式退出时间重建。不存在算法选择器。空间质量默认为 `"high"`，保留原有的 3 个切片和每侧 3 步。预设选择固定的 GPU 特化采样数：

| 质量 | 切片数 | 每侧步数 | 每评估像素深度采样数 |
| --- | ---: | ---: | ---: |
| low | 1 | 2 | 4 |
| medium | 2 | 2 | 8 |
| high | 3 | 3 | 18 |
| ultra | 9 | 3 | 54 |

这些是 Intel XeGTAO 的预设计数。XeGTAO 按切片数归一化，并将其用于切片/步进噪声索引。预设仅更改采样数，不改变效果半径、强度、渲染分辨率、空间降噪或时间历史。Low 质量可能丢失细节或闪烁更多；这是刻意的画质/性能权衡，而非声称保留高质量输出的优化。预设成本对于完整 SSAO 任务并不保证单调递减。仅当当前 AO 与历史均至少为 0.999 时，传输阶段才会跳过接收体；噪点更多的低采样估算会让明显更多的静止像素留在传输搜索中。同理，时间拒绝/统计与短历史重建具有信号依赖型成本。因此 Low 的估算 Pass 可能更便宜，但其完整任务却比 Ultra 更慢。仅显示 AO 视图仍然执行估算与每个已启用的时间 Pass；它只是用可见性拷贝替换最终场景着色/呈现。运动裁剪（Motion pruning）可以消除静态区域中浪费的传输工作，但它仍是一个依赖场景的可选特性。请勿静默启用它或放宽 AO/传输阈值来强行让总预设耗时按采样数排序。独立展示演示默认显式启用了现有裁剪选项；其复选框允许进行无裁剪对比。运行时 API 本身仍保持按需启用。这避免了在不改变采样或历史数学的前提下将大部分静态场景预算消耗在搜索噪点化的静止 AO 像素上。

估算器管线缓存在按质量键控的记录中，每个所有者拥有一个空间解析管线。未变更的帧不分配新的管线/缓存键/容器。Full 与 Half 所有者接收相同的预设；Half 在缩小的几何网格上使用原相机投影进行评估。更改质量会重置时间历史而不重新分配公共输出。首次执行未缓存的质量时使用同步 `createComputePipeline`；API 不暴露异步质量预热操作。切换到已缓存的质量会复用其管线。对首次使用卡顿敏感的应用应考虑该初始化开销，而非假设质量切换总是零分配的。不支持的预设字符串会在任何派发之前在任务边界显式失败。可变设置在 API 边界校验，并在每次派发前采样。强度位于 [0,1]；半径为正有限数。强度保持原有的单位增益，在时间滤波前解析为 `clamp(1 - intensity * (1 - rawVisibility), 0, 1)`。零保持中性，负可见性绝不会进入历史。不引入直接光、高光、自发光或材质基础颜色调整。

支持使用全目标视口的透视与正交投影。SSAO 管线目前仅支持左手坐标系构建。右手坐标系几何法线附件的 Z 约定不同，因此在 `babylon-lite-rh` 构建中创建任务会显式失败。局部视口相机也会显式失败，因为计算假定视口覆盖整个渲染目标。MSAA 深度必须先通过现有的 `createDepthResolveTask`。法线输入必须匹配源维度；默认为有符号单位视图法线，或经视图旋转变换的世界法线。缺失法线时，在估算、时间滤波/历史捕获以及半分辨率上采集中使用共享的九抽头深度重建。在内部像素处，按原始设备深度中更小的二阶外推误差 `abs(2*neighborDepth-secondNeighborDepth-centerDepth)` 选择每一侧的单边导数。与线性视图深度不同，设备深度在透视投影平面上是仿射的。仅比较相邻视图深度差可能跨过连续深度折痕选择采样、凭空捏造中间法线，并导致双边上采样器找不到兼容的接收体采样（白色空洞）。使用所选直接邻域的解码视图位置做叉积；对其进行归一化，退化时使用 `(0,0,-1)`。如果两个二环方向都无法在原始深度的 float32 舍入误差界（`max(centerDepth, immediateDepths)*4*2^-23`）内外推出中心，则由可用的相邻行/列的对角采样提供平面一致性检查。这同样处理两张不同面之间的细条带，而不仅是背景和图像边界。将外推残差评估为一阶差分之差，以避免不必要地加倍原始深度带来的相消误差。绝不选择背景作为导数端点。当直接切线跨越轮廓线时，在所选相邻行/列上使用有效对角线推导该切线，而不是跨越到另一张面或远平面深度。这些有界轮廓回退仅在受影响像素处增加读取。如果在对角检查后轴向导数仍然不一致，且直接模板完全被覆盖，则评估由相邻/正交一环方向构成的 16 个局部三角形。在第一环和四个二环轴向抽头（包含中心共 13 个唯一深度采样）中，选择拥有最多一致抽头的以中心为锚点的原始深度平面。要求至少六个共面采样、残差不超过两倍舍入界限，且支持度严格高于现有切平面，才予以替换。这避免在曲面三角化表面上接受偶然的三角形/四边形拟合。该有界回退处理两条轴向模板都碰到其他面的细窄接收体。它仅针对不一致的模板运行，不针对普通平面像素或提供法线的变体运行。不使用运行时索引的局部数组来实现该搜索：将八个环采样、四个二环采样及其常量偏移保存在 `vec4f` 值中，用三次向量化比较统计支持数，并在严格改善 `best` 时记录获胜三角形的两个深度/偏移。候选顺序（相邻对，然后间隔两步的对）与算术不变。动态索引的 `array<f32,12>`/`array<vec2i,12>` 局部变量在常见 GPU 上会溢出到慢速内存：在 1080p Kitchen Half 管线无提供法线场景中，该搜索在约 15% 的像素（边缘与掠射角舍入处）触发，在全尺寸上采样中耗时约 0.12 ms、准备阶段耗时约 0.04 ms；向量化形式大约将其减半。图像边界保留单边选择，单像素维度保留退化法线回退。这是一个共享着色器辅助函数，而非独立的法线纹理/Pass 或更弱的兼容性规则。提供法线的变体完全绕过重建。法线纹理绝不进行 gamma 解码。

数值回归构建在亚像素折痕处相交的解析投影平面，并带有相邻背景轮廓或留下窄接收带的前景遮蔽体。它将 GPU 重建法线与平面对比，并用提供法线和重建法线对常数 0.25 稀疏 AO 进行上采样。每个被覆盖的内部像素必须在一个半精度浮点步长（1/4096）内保持 0.25，不得回退为白色。在完整平面模板可用处，法线一致性必须至少为 0.999；轮廓回退法线必须保持与其所属面兼容（点积 0.9）。`task.normalTexture` 是可变的：赋予兼容的有符号法线目标即可采样它，或设为 `null` 以从深度重建法线。在 Full 模式下，在这些变体间切换会使估算器管线失效并重建时间所有者，重置历史但不替换公共可见性。在 Half 模式下，它会重建缩小输入/估算/重建所有者及全尺寸输出，因为输入准备与最终上采样具有不同的着色器变体。托管输出目标保持不变；PBR 绑定会跟随底层纹理替换，其他预录制消费方必须重新录制其帧图。用相同格式的另一个法线目标替换仅重新绑定源并重置历史。无效格式、多重采样或尺寸不匹配/未构建均会显式失败。任务绝不拥有或销毁任一法线源。同一选择会传播到输入准备和双边重建；未变更帧保留缓存资源。

## 内部架构

内部 GPU 所有者不持有场景引用。它拥有缓存的计算管线、uniform、五级视图深度金字塔、点采样钳制深度采样器、一个打包 AO/边缘工作纹理、哑法线绑定以及最终可见性目标。任务使用引擎编码器驱动它。源保持借用状态。GPU 对象仅在工厂/构建/调整大小或工作模式变更时创建，而非逐帧创建。绑定组仅在源或分配标识变更时重建。设备替换会使所有者的 GPU 状态失效。

任务通过一个稳定的托管 `RenderTarget` 为其输出纹理提供别名。重建帧图会调整该输出大小并重建依赖绑定，与现有帧图后处理任务一致。销毁是幂等的，不会销毁源深度/法线附件。

## 管线配置

1. 将反向 Z 深度拷贝到视图深度 mip 0（`r32float`）。
2. 加权归约到 mip 1..4（`r32float`）。
3. XeGTAO 估算器：一个 `r32uint` 工作纹理，保存打包可见性字节（0-7 位）和打包边缘字节（8-15 位），保留上游字节值。解析阶段每抽头仅读取一个字，而非两张纹理。
4. XeGTAO 边缘感知降噪写入重建暂存目标。
5. 默认的时间累积、AO/深度卷积、历史修复以及空间重建写入稳定的 `rgba16float` 可见性。显式退出时间重建时，步骤 4 直接输出至可见性并跳过步骤 5。

每次归约派发仅读取其前一级 mip 视图并写入一个目标 mip 视图。这避免了原生参考使用的五个同时存储绑定，从而遵守基线 WebGPU 限制。8x8 工作组对输出坐标执行边界检查。奇数尺寸归约包含最后一行/一列源像素；一维及微小目标依然合法。

Uniform 布局：176 字节。前 96 字节匹配原生 GTAO 常量：size(u32x2)、倒数尺寸、深度解包、tan 半视场角、NDC 乘/加、逐像素视图缩放、半径/衰减、半径乘数/填充/最终幂次/模糊 beta、采样幂次/薄补偿/mip 偏移/噪声索引。接下来依次是正交标志、强度、两个保留的零填充值（共四个 f32），最后是视图矩阵。提供法线/世界法线选择通过管线 override 特化，而非逐帧分支。偏移为显式类型化数据，绝不从生成的 WGSL 解析。

## 着色器逻辑

### 深度

视图深度为 `depthUnpack.x / (depthUnpack.y - reverseDepth)`。归约使用原始 XeGTAO 相对于最远深度的加权平均：有效半径 = `0.75 * radius * 1.457`，衰减 = `0.615 * effectiveRadius`，权重钳制到 [0,1]。不使用 min/max Hi-Z 替代。

### XeGTAO

使用静态相位零的上游 Hilbert/R2 空间噪声、二次近场采样、像素对齐切片采样、最近 mip 选择、法线的投影切片长度校正、余弦加权地平线积分、半径衰减、最终幂次 2.2 以及最小可见性 0.03。保留参考版的快速平方根与反余弦近似以确保算法对等。打包工作 AO 为 round(visibility / 1.5 * 255)。左/右/上/下斜率调整边缘使用原始的两位打包。深度采样使用点采样钳制采样器（`textureSampleLevel`，最近 mip 与纹素），类似于 XeGTAO 的 `g_samplerPointClamp`。逐采样尺寸/层级查询和手动钳制曾使估算器在 Full/High 下慢了约 40%。边缘在水平线循环之后打包：在循环期间持有它们会增加寄存器压力。

### 内存访问

这些 Pass 受限于读取延迟与带宽而非算术运算，因此：

- `aoRawDepth` 使用 `ao.size` 钳制，绝不使用 `textureDimensions`：原始深度始终具有 AoParams 尺寸，而尺寸查询会在每次深度读取前串行阻塞。派生自 uniform 的尺寸同样替代了解析阶段（`ao.size`）与 Half 准备阶段（`ceil(size / 2)`）中的查询。
- 独立的逐像素输入（通过 `aoSuppliedNormal` 获取的提供法线、视图深度、速度、传输、当前/历史 AO 及计数、解析字）在背景或收敛测试之前以及在依赖拒绝算术之前读取，使其延迟相互重叠而非串行跟随每个分支。
- 工作组内存由 WGSL 零初始化；运动掩码依赖该特性，而不是在额外屏障后清除其标志。

重排加载指令不改变任何算术。在 1920x1080 下，它将时间累积从 0.120 降至 0.092 ms（Full/High），将解析从 0.036 降至 0.032 ms；原生与时间校验保持不变。

降噪使用原始对称边缘权重、对角权重、边缘泄漏修正、中心权重 1.2 与最终缩放 1.5。在转换到半精度浮点输出之前先饱和转换到上游最终 8 位值。任何物理画质更改都不会伪装为移植修正。

背景为中性可见性 1。禁用的任务将输出清除为白色一次，而不是继续执行所有 AO 工作。深度遵循生产者的反向 Z 契约：零为清除/背景值，支持范围内的每个正设备深度均为几何体。累积、几何历史校验、修复/输出、传输或运动掩码中不存在与相机无关的深度 epsilon。例如，near 0.01、far 20000 与视图 Z 10000 会产生约 `5e-7` 的合法 float32 深度；将其作为背景拒绝会抹除本来有效的 AO。现有的标量设备到视图转换辅助函数 `dZ` 位于共享的 AO 参数前导代码中，被深度准备、法线重建、Half 上采样与时间重建共同复用。现有视图深度钳制保留在各自调用点；向量化转换保持向量化。

## 状态机与生命周期

创建 -> 分配输出/资源 -> 录制源 -> 逐帧执行。
调整大小/帧图重建 -> 替换所有者资源与绑定组 -> 发布输出。
设备变更 -> 重建所有者 -> 重新发布输出。
禁用 -> 中性化一次；启用 -> 恢复当前帧计算。
销毁 -> 销毁自有资源一次并分离输出状态。

无效维度、不支持的相机模式、缺失源附件、多重采样输入以及无效可变设置均作为显式错误抛出。

## Babylon.js 等价映射

并非 SSAO2 对等。这是一个独立的 XeGTAO 实现。未使用的特性不会影响 Babylon 一致性及无关打包。尽管如此，场景 348 仍在相同环境光照的 Kitchen 上将随附集成与 Babylon.js `SSAO2RenderingPipeline` 对比，作为粗略回归界限而非等价性声明（见测试规范）。

## PBR 集成里程碑

`enablePbrSsao(scene, task, materials?)` 是一个显式异步启用器，在 `registerScene` 之前调用。它仅向选定 PBR 材质（默认为所有 PBR 场景材质）挂载材质插件，保留已存在的插件。该插件适用于不透明与 alpha 测试的 PBR 漫反射 IBL，不适用于直接光、自发光、无光照、透明、折射、阴影或几何输出 Pass。仅使用 AO 相机的消费 Pass 采样其可见性。使用其他相机（包括辅助视图或反射/探针相机）或无相机的 Pass 改用现有的中性白色纹理：它们正常渲染而不会借用另一视图的遮蔽。使用 AO 相机的 Pass 仍必须具有相同的有效纵横比；投影不匹配仍属于显式配置错误。Pass 发布用于打包其场景 UBO 的实际经视口调整后的纵横比，包括启用 `RenderTaskConfig.cs` 时的画布尺寸。校验使用该值，而非物理离屏目标形状：使用 AO 相机画布纵横比投影的正方形目标是合法的。任务绑定到单个所属场景。新材质挂载发生在场景注册之前；对已挂载材质重复启用是幂等的。共享源材质保留单个派发器插件。其弱消费场景映射在绑定组创建前与动态更新前选择每个场景自身的采样状态；未参与的场景采样引擎自有的中性白色。相机选择与纵横比校验仅适用于选中的参与场景。销毁仅移除该场景的成员身份，并在最后一个成员离开后分离派发器。首次挂载与最后移除会使已缓存的 PBR 特性选择失效，包括已在另一个场景中组合的材质。

屏幕可见性在从材质世界位置与当前场景视图投影重建的归一化坐标中采样。现有的烘焙材质 AO 与屏幕 AO 通过 `min` 组合，而非相乘两次。一个可选表达式修改器将漫反射 IBL 标量从 `occlusion` 更改为 `min(occlusion, ssaoDiffuseVisibility)`。这在清漆、光泽与次表面合成之前修改 `finalIrradiance`，而不是从已合成颜色中减去。独立的光泽/折射环境波瓣不单独遮蔽。高光/GTSO 与弯曲法线处理不会通过最终颜色相乘静默近似。

材质插件支持选择匹配的仅 IBL 着色器与绑定变体，并获得一个内部资源版本回调。未启用时，可空绑定装饰器与可空漫反射 IBL 表达式修改器会被折叠移除。常规片元/顶点插件桥接按签名保留单个片元。仅 `enableDynamicPbrBindings` 通过可空的 `pbr-plugin-decorator.ts` 接缝安装 `pbr-plugin-passes.ts` 装饰器。它复用活动桥接构建完整与排除 IBL 的签名，为每种 Pass 策略分配独立标识，并仅保留不可变片元索引与已启用名称。这使得仅 IBL 过滤、动态租约选择与策略签名不会进入仅使用普通材质插件的场景。当顶点资源桥接在 SSAO 启用器之前或之后安装时，应用相同的装饰器。动态绑定复用现有的渲染束失效机制。替换绑定组接收原始场景资源标识与绑定销毁器集合，保留诸如纹理区域光等上下文扩展。表达式安装器隔离在 `pbr-diffuse-occlusion.ts` 中，不从惰性导入的 IBL 片元命名空间导出。对内部 `createIblFragment` 工厂的现有三参数调用保留原行为。可选的第四个 `WgslSource` 参数选择漫反射遮蔽并默认为 `occlusion`；它不是新的根包 API。扩展在创建片元前解析已安装的修改器，无需修改时传入 `undefined`。工厂精确生成一次选定计算，不产生多余计算辅助函数或被丢弃的默认着色器字符串。不解析或修补生成的 WGSL。预烘焙天空盒计算绕过表达式选择与普通 IBL 生成。特性选择发生在可选片元钩子处，而非通用生成器内部。绑定装饰器在缺席时有显式早退，使下游压缩器能复现原始未装饰返回路径而无多余可空调用临时变量。AO 输出替换时，受影响的绑定组在渲染前刷新，已缓存的不透明渲染束重建一次。未变更帧保留常规缓存渲染束路径，不创建 GPU 对象。几何/阴影 Pass 排除 AO 插件，在生成其深度/法线时无法从 AO 输出形成反馈环。

动态绑定组及其纹理租约按可渲染对象、管线以及渲染任务的稳定 `DrawUpdateContext` 标识缓存。绑定组在首次更新时、在插件内部 `_prepareDraw` 钩子为 Pass 相机选择正确资源后惰性创建。每个绑定保留其自身选定组，因此在任一绘制前更新两个 Pass 不会互相交叉污染，即使两者使用相同的材质/可渲染对象与 GPU 管线。选定的 AO/中性变体是绑定令牌的一部分。更改 Pass 相机刷新该 Pass 的组；跨 Pass 交替未变更相机不会每帧重建组或使渲染束失效。每个受监视插件的令牌独立比较而非求和，使相反的选择变更不会互相抵消。场景选择仍在相机选择之前运行。销毁、输出替换与设备替换保留带栅栏的纹理代次租约。绑定用户对每个缓存 Pass 状态进行引用计数。成功的代次替换、网格移除与任务销毁会退役其被移除的绑定；候选回滚保留由存活代次持有的绑定。最后一个绑定用户立即移除其缓存状态并调度其纹理租约进行带栅栏释放，即使网格依然存活。保留一个网格生命周期清理回调作为回退，而非为每个临时 Pass 或输出调整大小保留一个回调。这些冷退役钩子与 Pass 纵横比发布器仅由动态绑定启用器通过 `render/draw-binding-lifecycle.ts` 安装，并从普通 Pass 中折叠移除。

特性拥有采样纹理租约、中性回退及旧代次退役。材质仅捕获采样纹理状态对象，绝不捕获场景或 AO 任务。销毁恢复中性采样并遵守排队中的 GPU 工作及材质持有的纹理引用。动态纹理被排除在网格的静态纹理租约列表之外：仅其当前绑定组代次保持它们存活。当引擎设备变更时，白色回退会重建，包括在 AO 任务发布其替换输出之前的材质重建期间。

## 时间 AO

重建由 `createSsaoTask` 在 PBR 合成之前初始化：

```ts
interface SsaoTemporalOptions {
    enabled?: boolean;
    velocityTexture?: RenderTarget;
    velocityHasPreviousDepth?: boolean;
    historySamples?: number;
}
interface SsaoTemporalSettings {
    enabled: boolean;
    historySamples: number;
    resetVersion: number;
}
function resetSsaoTemporal(settings: SsaoTemporalSettings): void;
```

例如，`ao.quality = "medium"` 为每个评估像素选择 8 个空间深度采样。独立地，`createSsaoTask({ depthTexture, camera, temporal: { velocityTexture, historySamples: 8 } }, engine, scene)` 将成熟时间历史上限设为 8 次观测。修改其中任一项不会改变另一设置或隐式启用/禁用半分辨率。

运动掩码裁剪是一个独立的、默认禁用的优化：

```ts
interface SsaoMotionPruningSettings {
    enabled: boolean;
}
function enableSsaoMotionPruning(task: SsaoTask): SsaoMotionPruningSettings;

const ao = createSsaoTask({ depthTexture, camera, temporal: { velocityTexture, velocityHasPreviousDepth: true } }, engine, scene);
const temporal = ao.temporal;
const pruning = enableSsaoMotionPruning(ao);
pruning.enabled = false; // Restore unpruned transport for a highly dynamic scene.
```

在带物体速度构建的 AO 任务上调用裁剪启用器。缺失速度与已销毁任务会显式报错。重复调用返回同一纯设置对象。调用启用器即启用（`enabled: true`）；省略它则保留原始传输搜索，不包含掩码着色器、掩码分配、分类或归约派发、层级查找或间接绘制缓冲区。该独立模块会从仅使用时间滤波的使用方中 tree-shake 剔除。

对 `enabled` 的修改应用于下一执行的 AO 帧。启用时分配可选资源并选择带掩码的传输管线；禁用时销毁这些资源并恢复原管线与直接绘制。两种转换都不会重置时间历史或替换公共 AO 目标。禁用时间滤波也会释放可选掩码；如果仍请求裁剪，重新启用时会重建它。调整大小/设备/源变更以及销毁遵循时间所有者的生命周期。未变更帧不创建 GPU 资源。这改变的是工作选择而非 AO 画质；收益取决于运动覆盖范围与 AO 半径，密集运动可能使其额外的分类/查询开销得不偿失。

时间默认值：启用，累积 16 个历史采样（原生重建长度）。`historySamples` 为 `[1,16]` 内的整数。`resetVersion` 为非负安全整数；重置函数为其递增以应对显式相机切换或外部场景内容变更。禁用时间滤波恢复静态相位零与原始纯空间输出。所有现有原生黄金图保持不变。

现有的接触/GI 时间所有者提供仅相机、深度校验的累积，但缺乏物体速度、法线拒绝与逐像素历史置信度。复用其运行均值/相位约定，而非其 GPU 解析器。AO 拥有专用的原生格式全屏重建管线；不需要全场景 TAA。活动实现及精确原生/生产契约见 [重建管线与所有权](#重建管线与所有权)。

可选速度目标是同尺寸、单采样有符号浮点 RG/RGBA 纹理。XY 等于上一帧减当前帧 NDC 位置的一半，Y 轴向上，与 `GeometryTextureType.LINEAR_VELOCITY` 匹配。解析器仅在转换到自顶向下纹理坐标时翻转一次 Y 符号。没有速度时，上一帧视图投影为静态几何提供仅相机重投影。有有效速度时，支持刚体/物体运动；仅 XY 输入保守地拒绝深度变化的运动。启用 `velocityHasPreviousDepth` 需要有符号浮点 RGBA 输入，并在 Z 中包含上一帧正视图深度。当在浮点 RGBA 目标上调用 `enableGeometryVelocity(geometry, { previousDepth: true })` 时，原生 PBR 线性速度输出将该值作为透视投影的上一帧裁剪 W 提供。Float32 速度保留 `1e-5` 的相对上一帧深度容差；半精度浮点速度对深度和运动使用 `2^-10`，且静态接收体代入精确的仅相机上一帧深度（见下文时间重建）。独立演示使用 `rgba16float`；裁剪保持逐字节等价。历史接受与遮蔽体材质点重建使用该上一帧表面深度，而非当前表面位置的旧相机投影。带有有效 3D 运动的独立移动接收体不会被盲目封顶，仿佛它是变化遮蔽体下的静止接收体。辐射度变化检测仍处理该表面上真正的 AO 变化。实时骨骼与变形网格从 PBR 与 Standard 几何 Pass 接收感知形变的输入速度，详见[模块 31](31-geometry-renderer.md)。初始显式不支持浮动原点时间重投影。

PBR 几何速度路径绑定逐可渲染对象 `gm` uniform（80 字节）：从当前到上一帧的世界矩阵，后跟启用/填充 vec4f。当世界版本变更时，计算 `previousPackedWorld * inverse(currentPackedWorld)`；在应用上一帧视图投影前将其应用于已变换的当前世界位置。在随后的静态帧上将增量重置为单位矩阵。首帧与被排除网格选择当前裁剪坐标。逐网格 uniform 随几何代次销毁；共享材质视图绝不保留另一网格的上一帧世界缓冲区。注册与世界版本变更使用一次无分配求逆尝试，缓存至下次变更。其奇异性阈值相对于绝对行列式项之和，而非绝对网格尺度截断；微小可逆缩放（包括 `0.0001`）合法。对于被跟踪网格，奇异、非有限或 GPU 不可表示的逆矩阵会显式失败，绝不代入单位矩阵。被排除/隐藏网格保持中性，恢复跟踪时必须具有可逆变换。对于变形网格，上一帧变形权重与上一帧四/八影响骨骼矩阵在应用上一帧世界/视图投影前重建上一帧局部位置。两种形变可以同时变化；首帧、隐藏与被排除历史初始化为中性。独立动画薄实例、烘焙 VAT 及任意自定义图变形仍属于独立速度契约。该逐网格状态及其顶点 WGSL 位于 `material/pbr/pbr-geometry-velocity.ts`，仅由显式的 `enableGeometryVelocity` 启用器保留。可空实现接缝在普通 PBR 几何场景（包括历史上的仅相机速度 Pass）中折叠移除。AO 生产者在场景注册前按需启用；时间消费者仍使用其独立的 `velocityHasPreviousDepth` 选项。这些可选模块的错误码分配在既定核心/计算/无障碍错误之后，使未使用特性不会重新编号并增大普通场景。库构建同样将 SSAO/速度模块及其绑定接缝追加到入口遍历末尾，遵循现有可选无障碍规则。否则新条目可能重排普通生成导入并扰动压缩器命名，即使没有任何 SSAO 代码在 tree-shaking 中存活也会增大无关场景打包体积。

估算器相位在 64 帧间循环。XeGTAO 使用其现有的 Hilbert/R2 时间偏移，相位零与上游适配器完全一致。关闭时间滤波的估算始终使用相位零。

### 生产重建

默认重建控制器选择完整的原生格式所有者：R8 AO 反馈、R16 观测计数、一张全分辨率 RG32Uint 几何历史、AO/深度卷积、历史修复以及空间重建。提供速度时额外启用几何驱动的遮蔽历史传输。可选运动裁剪改变工作选择，不改变重建或历史策略。不存在独立的引导历史、置信度收尾模糊或强制运动活动层级。

### 时间生命周期与回归范围

历史/相位在分配、调整大小、设备或输入标识变更、投影/裁剪平面变更、半径/强度变更、启用状态切换、采样上限变更、显式重置以及大幅相机切换时重置。普通相机运动会进行重投影而不是每帧重置。自动相机切换启发式将平移量与 `max(1, radius * 8)` 世界单位比较，并将当前/上一帧前向向量点积与 `0.7` 比较。它是固定的，而非公共调优参数；因此场景尺度与 AO 半径会影响触发重置的时机。对于已知切换请使用 `resetSsaoTemporal(ao.temporal)`，不要依赖该启发式识别每一次切换。如果 `executionEnabled` 在其速度生产者继续运行时跳过了 AO 任务，在恢复前请显式重置；`enabled` 是受支持的中性输出开关。禁用会清除中性输出并使历史失效；销毁会释放私有纹理/缓冲区一次。矩阵存储与参数暂存区被复用；无逐帧管线、绑定组或临时矩阵分配。

### 重建管线与所有权

默认时间所有者保留稳定的公共 AO 目标，并将空间估算重定向到私有暂存区。它拥有两份反馈历史、一份几何历史、一个时间中间纹理、一个五级 mip AO/深度卷积纹理以及一个重采样中间纹理。未变更帧不发生分配或绑定组创建。

AO 反馈、时间 AO、卷积 AO 与修复后 AO 使用 **R8_UNORM 渲染附件**，匹配原生采样与渲染目标转换。计数使用独立的 R16_FLOAT 附件；卷积深度使用 R32_FLOAT。几何历史为 RG32_UINT：原始设备深度的精确位，然后是以两个 snorm16 值（约 5e-5 rad）编码的八面体有符号世界法线。设备深度绝不量化，法线误差远低于 0.9 一致性余弦与 1e-4 平面容差，因此法线拒绝契约保持不变。将每个八面体通道显式编码为 `round(clamp(e, -1, 1) * 32767)`，对有符号整数执行 bitcast，然后组合低 16 位 X 通道与移位后的 Y 通道。这保留了 snorm16 表示而不调用 `pack2x16snorm`：某个云端 GPU 后端尽管传入了正确的法线与逆视图输入，但在运行时对 `(1, 1)` 返回了零，导致有效历史被拒绝。保留端点/半球 GPU 往返回归以及严格的两帧历史计数检查；切勿用宽松断言掩盖它。仅需一张几何纹理：传输与时间累积读取上一帧几何，随后现有的最终输出 Pass 用当前深度/世界法线覆写它以供下一帧使用。该最终 Pass 绝不采样几何纹理，后续重建阶段直接使用当前源几何。这消除了几何乒乓缓冲而无需增加 Pass。在 1920x1080 下，单份历史为 15.82 MiB（两个 RGBA32F 通道曾为 63.28 MiB）；AO/计数/几何持久历史总计 27.69 MiB。工作分辨率与所有反馈格式保持不变。早期的单 RGBA32_FLOAT 历史（43.51 MiB 历史）受带宽瓶颈限制：在 1920x1080 Full/High 下，它在输出 Pass（16 字节写入）多耗时约 0.020 ms，在时间累积（四次 16 字节双线性读取）多耗时约 0.013 ms（已扣除解码开销）。基于字节值的 RGBA16F 计算原型未能匹配原生 UNORM 采样/转换，未予保留。每个阶段渲染全屏三角形，每个 mip 与历史通道拥有独立缓存的附件视图。空间重建与输出合并为单一全屏 Pass，包含三个 MRT 目标：R8 反馈、稳定的归一化 RGBA16F 公共输出（与 R8 值精确一致量化：`floor(clamp(ao,0,1)*255+0.5)/255`）以及几何历史。原生历史长度为 16，这也是接受的最大 `historySamples` 值。

省略当前法线输入时从深度重建法线；这些法线仍存入几何历史。在 Half 模式下，准备阶段从全尺寸源深度重建一次缩小法线，最终上采样器重建全尺寸接收体法线。所有估算与历史资源匹配当前工作分辨率。Full/Half 切换会替换 GPU 与时间所有者、重置历史并重新发布全尺寸输出。即使禁用时间滤波也会重建绑定，以防重新启用时恢复引用已销毁资源的绑定组。

一项孤立的 R32_FLOAT 历史试验保留了生产辐射度、抖动与传输控制，并将法线/曲率拒绝替换为原生 1% 视图深度接受。它在 1080p 下可将几何历史降至 7.91 MiB，AO/计数/几何总历史降至 19.78 MiB。它通过了近距离 Half 模式暂停/反转用例，但未能通过默认移动球体表面闪烁预算：时间/空间 RMS 比为 0.589，而法线感知历史为 0.477（上限 0.5）。遮蔽表面长历史保持率从 94.97% 降至 60.33%。它还在相同深度的法线不连续处保留了陈旧 AO。该试验并非发布模式；带精确深度的法线感知历史仍为默认。

几何历史存储精确的当前设备深度。时间重投影使用上一帧相机空间中的当前世界位置以及来自 3x3 反向 Z 深度搜索的最近物体运动。参考模式精确使用原生仅深度接受与运动精度。逐抽头上一帧深度一致性为相对视图深度误差低于 1%；双线性坐标钳制到屏幕边界。在加载先前的几何/AO/计数前先计算每个双线性抽头的权重。精确零权重抽头无法影响这些有限历史累积；跳过它们的几何重建、归一化与纹理加载。当抽头存储的法线字等于当前世界法线的编码时，其上一帧视图法线即为已计算的 `previousNormal`；曲率精确为零。复用这一事实，避免再次变换/归一化同一法线。非相同法线保留原始曲率计算；法线拒绝、平面容差、局部性与置信度不变。生产模式额外检查世界法线一致性（点积至少 0.9）、拒绝无效/背景先验几何、尊重来自 RGBA 速度的正上一帧视图深度，并在可见性跳变超过 0.5 时重启像素。有了精确的上一帧表面深度，直接使用接收体自身的 XY 运动而非膨胀后的邻近物体运动。生产逐抽头接受使用上一帧视图切平面，基础容差为 `max(1e-4,min(previousZ*0.005,radius*0.025))` 加上曲率余量 `0.5*length(deltaPosition)*length(deltaNormal)` 以及至多两个 AO 半径的局部性。原生 1% 仅 Z 检查会拒绝合法的低分辨率曲面抽头，因此不使用。RGBA 上一帧深度路径直接从提供的材质点负载初始化上一帧像素、运动与上一帧深度。请勿先计算结果会被覆写的仅相机世界重建/投影。当提供的上一帧深度与静态仅相机上一帧视图深度在 `max(1e-4, abs(cameraZ) * tolerance.x)` 内一致时，为当前 NDC `v` 代入该精确 `cameraZ = dot(reprojectW, v) / dot(inverseW, v)`。两行分别为在 CPU 上以双精度组合的 `previousVP * invVP` 与 `invVP` 的第 3 行。静态接收体随后对 RGBA32F 与 RGBA16F 速度均完全一致地重投影；仅真正移动的接收体受源精度影响。仅 XY 速度与仅相机路径保留其原始重投影数学。它们不引入宽泛的裁剪引导或移动保底历史上限。生产反馈同样避免 R8 累积死区。当成熟像素的混合更新低于半个 R8 色阶时，使用空间旋转的位反转帧序列应用有界无偏量化抖动。包含带有 1 个 float32 ULP 算术余量的精确半色阶边界（`0.5/255 + 1/8388608`）；排除该边界会使 8 色阶阴影在原生 16 帧混合下永远卡住。否则在 4 帧混合下旧阴影可能永久保持暗 2 个色阶，或在 16 帧混合下暗 8 个色阶，即使当前 AO 为纯白也是如此。新/重置像素不执行抖动。抖动严格处于半个色阶以内，因此已经为白的背景与稳定白色接收体保持精确白色。不对未变更观测（`abs(current-old) <= 1/8388608`）执行抖动；白色端点附近的渲染目标转换否则可能偶尔把已清除像素向下移动一个字节。当当前/历史 AO 相差不超过 1 个 UNORM8 色阶加半个输入半精度浮点 ULP（`1/255 + 1/4096`）时，不因运动而降低生产置信度。原生严格不等式否则会将未变更的白色 AO 视为超出零方差包络并错误地丢弃移动表面历史。当该未变更观测条件成立时，方差包络不可能降低置信度，且大幅变化条件不可能触发。完全跳过未使用的 3x3 AO 统计、运动因子、平方根及 gamma 计算。否则保留原始邻域求和顺序、严格包络与置信度更新。这是工作消除，而非放宽裁剪或更改历史限制、R8 量化、抖动或重建。Uniform 控制为重置、最大采样数、保留通道以及上一帧深度契约。逆视图投影重算在普通未变更帧上缓存；镜头切换/投影变更使其失效。

四分之一分辨率历史实验已随不支持模式一并移除。其仅偏下裁剪抑制了拖影，但放大了局部接触阴影闪烁，即使在 Ultra 画质下也是如此。运行时保留已接受的不含该裁剪启发式的 Full/Half 时间响应。

### 重建阶段

生产历史传输默认运行原始无掩码搜索。`enableSsaoMotionPruning(task)` 单独启用保守的物体运动图块层级。其纯 `enabled` 设置支持场景专属的实时开关。8x8 工作组将提供的材质运动与仅相机重投影对比，并通过工作组原子操作将单个图块内符合条件的像素按位或汇总。整个层级存放在单个 `STORAGE | COPY_DST` 缓冲区中（`ssao-object-motion-mask`，包含 `ssaoMotionMaskCellCount(w, h)` 个由四个 u32 组成的单元，各层级连续排布）。每个单元以 `(~minX, ~minY, maxX, maxY)` 存储其活动基础图块的包含式像素空间包围矩形，而非整个 mip 单元的占用标志。非空基础图块贡献其裁剪后的 8x8 像素范围。因此将缓冲区清零即编码了空矩形 `(0xffffffff, 0xffffffff, 0, 0)`。掩码 XY 阈值为 `0.025 + |suppliedMotion| * tolerance.y * 0.5` 个工作像素，保守低于传输搜索的 `0.05 + |suppliedMotion| * tolerance.y`；其上一帧深度测试与传输阶段相同。背景/重置像素贡献零。每个运动图块的首个通道在同一次派发中对四个分量执行 `atomicMax` 更新每一层级：第 m 级单元为 `min(tile >> m, levelSize_m - 1)`，精确复现了原先拉伸奇边缘 mip 归约的并集。每帧模块清零单元缓冲区与四字间接绘制缓冲区，然后录制一次派发。存在运动图块时写入三个顶点与一个实例；否则清零后的绘制保持为空。被跳过的传输绘制将其区域清零，且不在完全静止的场景中搜索。

对于有绘制的传输 Pass，每个接收体从传输绑定 8 的只读存储缓冲区读取覆盖其精确钳制搜索圆的保守正方形。图块跨度覆盖该正方形的 mip 最多只需四次读取。将存储的活动包围盒与接收体裁剪后的像素空间搜索正方形相交测试。因此 512 像素 mip 单元中的单个移动物体不会激活整个单元。若无任何包围盒相交，则在 36 抽头搜索之前直接返回现有的零传输结果。否则按相同顺序原封不动执行原始搜索。该层级改变的是工作选择，而非位移、历史置信度或 AO 算术。独立的 `ssao-motion-pruning.ts` 模块拥有所有掩码分配、管线、绑定、派发、着色器守卫及销毁。时间控制器仅暴露一个内部可选的 GPU 准备回调。原生格式所有者暴露一个可选的传输扩展：其管线替换原始传输管线，其缓存资源追加到传输绑定中，并提供间接绘制缓冲区及执行/销毁钩子。所有者比较绑定扩展标识，从而在切换开关时重建 Pass 绑定而不销毁任何历史。

启用器仅在带速度的时间任务上安装准备回调。当时间滤波与裁剪同时启用时，它创建/重新绑定扩展；否则释放掩码并移除扩展。源标识变更会刷新掩码绑定而不替换纹理。尺寸/设备变更创建新所有者；销毁所有者时精确销毁其扩展一次。默认路径不导入裁剪模块或掩码着色器，也不录制任何掩码工作。带掩码的着色器向共享传输着色器生成器传入通用声明与搜索前注入参数，而不做字符串解析或替换。两条路径保留原始 36 抽头搜索与累积顺序，且模式切换保留历史索引、计数、AO 相位、反馈纹理与稳定公共输出。

1. 时间累积：当前局部无权重 3x3 均值/方差、原生依赖运动的方差 gamma 0.5..2.5 以及原生观测计数更新。保留原始无裁剪历史行为用于基线校验。让 R8_UNORM 渲染附件执行原生 AO 转换。
2. 卷积 mip 0：时间 AO 加上当前设备深度，由时间累积的 MRT 输出直接写入。时间中间纹理别名卷积 AO mip 0；不存在拷贝着色器/Pass 或独立 R8 纹理。四次归约复现原生 4/6/9 采样奇维度规则与求和顺序。AO 在每个 mip 转换为 R8；深度保持 float32。
3. 历史修复：对于低于 5 的计数，选择 mip `int(4*(1-saturate((count-1)/4)))`，逐级下降直至几何加权双线性覆盖率至少达到 0.995。使用原生小数虚拟 mip 分辨率、最近邻 AO 查找、双线性设备深度以及切平面权重 `saturate(1-abs(dot(delta,normal))*10/(1+viewDepth))`。
4. 空间重建与输出（单 Pass）：原生八点泊松盘与帧稳定 Bayer 旋转；半径 `4*(1-saturate(pow(abs((count-1)/8),0.2)))`。高斯权重为 `exp(-distanceSquared/(2*0.9*0.9))`，乘以几何权重。计数至少为 9 时绕过滤波器并保留修复值。
5. 同一 Pass 将最终 AO 写入 R8 并将重建值反馈回历史（匹配原生管线），同时将归一化公共可见性与当前几何作为另外两个 MRT 附件写入。它读取精确的当前深度附件，并计算与时间累积相同的有符号归一化世界法线，包括背景的零法线。两个几何消费方此时均已完成。

### 时间 GPU 接口与绑定布局

```ts
function createXegtaoTemporalGpu(
```

所有者保留 `scratch`、两份 `history`、两份 `counts`、一份 `geometry`、`convolution`、`convolutionDepth`、`repaired` 以及可选的 `closestMotion`/`transport` 纹理；384 字节 `uniform` 与 96 浮点 `data`；借用的源标识；原始/暂存空间解析绑定组；`index`、`disposed`、管线以及两个缓存的 `{ pipeline, group, pass: GPURenderPassDescriptor }` 阶段数组。它不拥有场景。内部 `XegtaoTransportExtension` 可选提供 `pipeline`、`resources`、`indirect`、`execute(encoder)` 与 `dispose()`。最后绑定的扩展标识单独缓存。工厂上不存在默认运动裁剪标志。卷积 AO 纹理使用 `ssao-xegtao-temporal` 标签，捕获观察器也匹配该标签。每个自有纹理支持采样、渲染与回读；仅 RGBA16F 暂存额外支持估算器的存储写入。卷积 mip 数为 `min(5,floor(log2(max(width,height)))+1)`。

除归约外，所有着色器在绑定 0 共享估算器的 176 字节 AO 参数。时间 uniform 由字节 0 处的当前逆视图、64 处的上一帧视图、128 处的上一帧 VP、192 处的四个控制浮点、208 处的当前逆 VP、272 处的上一帧逆 VP、336 处的 `tolerance`（x：相对上一帧深度容差，y：相对运动容差；float32 速度为 `1e-5`/0，`rg16float`/`rgba16float` 两者均为 `2^-10`）、352 处的 `reprojectW` 以及 368 处的 `inverseW`（共 384 字节）组成。时间绑定顺序为：AO 参数、原始深度、当前暂存 AO、最近运动、先验 R8 AO、先验几何、先验计数、时间参数、当前传输、当前法线、原始提供速度。目标为卷积 mip-0 R8 AO、下一帧 R16 计数与卷积 mip-0 R32 深度。三个附件每样本占用 7 个逻辑字节，处于基线 WebGPU 32 字节限制以内。AO 仍精确经过一次原生 R8 渲染目标转换；深度保持精确 float32。后续归约使用独立单 mip 视图与独立 Pass，因此采样/附件用途绝不重叠。

传输绑定为：AO 参数、当前深度/法线/速度、当前暂存 AO、先验 R8 AO、先验几何、时间参数。它写入 RGBA32：上一帧归一化 UV、上一帧设备深度以及正的投影物理 AO 半径（零半径表示无传输）。搜索三个径向环和十二个方向；偏移角为 `direction*pi/6`。忽略背景、物理/搜索半径之外或低于 0.005 接收体平面高度的点以及低于 0.05 像素的扣除相机运动。按距离平方衰减与正仰角余弦加权。拒绝恢复运动超过 `0.1 * searchRadius` 与其投影位移两倍两者较小值的点，或主要为法向而非切向位移的点。即使在扩展的离去阴影搜索期间，静态竞争也使用物理半径。环半径在其方向循环内不变。保留原始 f32 正弦/余弦表达式与环/方向顺序；不做角度近似、采样数削减或搜索足迹更改。在计算欧氏距离之前先拒绝位于接收体平面下方的采样。为仰角余弦复用同一平面点积。这保留了抽头顺序与所有接受阈值，同时避免了共面/平面下方采样的平方根计算。

归约绑定为前一级 AO/深度 mip 视图；目标为 R8 AO 加上 R32 深度。没有 mip-0 管线或绑定组。历史修复绑定为：AO 参数、当前深度/法线/计数、所有 AO mip、所有深度 mip、线性钳制深度采样器、点钳制 AO 采样器。点钳制采样器借用自估算器所有者，不在时间状态中重新分配或镜像；两个历史通道与源重绑定均复用它。仅当支持 `float32-filterable` 时才使用硬件线性深度；否则生成手动双线性纹理加载。修复目标为 R8。空间/输出 Pass 在绑定 0..5 绑定：AO 参数、原始当前深度、当前法线（或现有哑法线）、当前计数、修复后 AO 以及时间 uniform 缓冲区（用于其开头的当前逆视图矩阵）。它以目标下一帧 R8 反馈、原始托管 RGBA16F 可见性分配以及单一 RG32_UINT 几何历史为目标：在 WebGPU 附件对齐下每样本 20 字节，处于基线 32 字节限制以内。几何目标不会同时作为输入绑定。乒乓切换仅适用于 AO/计数反馈，不适用于几何；两个缓存历史通道采样同一张几何纹理。

无速度时省略运动与传输 Pass。有精确上一帧深度速度时，同时省略最近运动 Pass 的分配与派发：材质点重投影读取原始 RGBA 负载。仅 XY 输入保留原生最近运动准备。在源/尺寸/设备变更时重建绑定/所有者；未变更帧不创建 GPU 对象或 Pass 描述符。执行后翻转历史索引。销毁若安装了原始空间解析组则恢复它、仅销毁自有资源，且是幂等的。

原生输入为有符号世界法线。引擎输入可以是有符号视图法线或有符号世界法线；需显式转换。切勿将编码后的几何 `WORLD_NORMAL` 误认为有符号纹理。

### 遮蔽历史传输

每当提供速度源时，重建控制器都会使用此传输。额外的一个 Pass 在接收体的物理 AO 半径内搜索动态遮蔽体。从实际接收体运动与上一帧深度重建它们上一帧的世界位置，减去仅相机运动，并平均其位移。当速度契约提供上一帧正视图深度时，直接用它重建遮蔽体的材质点位置。采样旧可见深度仅作为仅 XY 源的回退，不能替代精确负载；其曲率误差在小型投影物体上尤其显著。静态与移动接收体使用相同的接收体相对传输。从接收体的速度与上一帧深度重建其上一帧材质点位置，对仅 XY 源使用相同的法线校验旧几何回退。低于 0.05 像素的接收体运动可以作为数值静止运动跳过该重建，但绝不能禁用遮蔽体搜索：先前的那道门限曾在蒙皮梁上固定顶点与弯曲顶点之间制造出一条可见接缝。速度包含精确深度时，还需将上一帧材质深度与仅由相机重投影得到的上一帧视图深度比较。差值超过 `max(1e-4, abs(viewDepth)*tolerance.x)` 即视为接收体运动，即使屏幕空间 XY 位移为零。这防止了仅深度移动将传输后的历史置于当前而非上一帧接收体平面上。可选运动掩码除其保守 0.025 像素 XY 阈值外，使用与传输相同的上一帧深度差异测试。否则沿视线移动的接收体可能被错误地排除在传输之外。

令 `receiverShift = receiver - previousReceiver`、`meanDynamicShift = sum(weight * occluderShift) / dynamicWeight`，以及 `support = dynamicWeight + staticWeight`。当仅有静止遮蔽体贡献时，使用零平均动态位移。相对于接收体的有效运动为 `relative = meanDynamicShift * (dynamicWeight / support) - receiverShift`。将其投影到当前接收体切平面，并在 `previousReceiver - tangentialRelative` 处采样上一帧 AO。这保留了静止接收体结果、保持移动遮蔽体历史在蒙皮权重过渡处连续，并处理静止遮蔽体下方移动的接收体。针对 `meanDynamicShift - receiverShift` 校验法线运动，保留与有效切向位移的关系以及所有现有的深度、法线、曲率和局部性检查。

将该虚拟位移后的上一帧接收体投影到上一帧相机中。保留原生长期累积与重建，而非紧缩且有噪点的颜色裁剪。当前观测绝不被替换或空间拓宽。全亮静止区域与重置帧跳过搜索。对于仍保留旧遮蔽的新近受光接收体，搜索最多两倍物理半径以保留离去遮蔽体的传输方向。当旧历史仍需移出像素时，其当前影响可能已经消失。将已传输接收体的有效时间混合上限约束为 `min(configuredLimit,clamp(projectedAoRadius/4,2,16))`。这种分辨率感知响应为极小足迹保留既定的四次观测上限、在 64 像素以上达到完整原生限制，并避免缩放期间出现生硬的质量模式跳变。其亚像素估算器场在世界空间平移下并非不变。为重建保留其几何合法的历史年龄：永久将该年龄封顶为 4 会每帧重复模糊并反馈阴影，造成额外拖影。新近/解除遮蔽像素仍接收原生修复与空间重建。未受影响区域与大足迹特写路径保留完整原生混合上限。静态与移动接收体均保留其几何合法的原生历史年龄。不恢复宽泛的裁剪引导。仅从存储世界法线与当前遮蔽体一致（点积至少 0.9）的抽头插值上一帧遮蔽体深度，重新归一化双线性权重并要求至少半数覆盖。固定的绝对深度跨度守卫在低分辨率下会丢弃几乎所有合法曲面采样，因此不使用。这防止了前景/背景混合，同时不会把陡峭但连续的表面误判为轮廓。拒绝跨上一帧深度不连续处重建的遮蔽体运动；同样用其实际投影运动约束恢复的 3D 位移。缺少这些守卫时，轮廓/背景插值会破坏推断出的运动。按距离衰减与仰角对物理遮蔽体支持度加权。在同一个支持度中衡量静止竞争遮蔽体。用 `dynamicWeight/(dynamicWeight+staticWeight)` 连续缩放移动遮蔽体的平均切向位移：静止遮蔽体贡献零位移，而非用阈值把整个历史场一刀切掉。先前的 `smoothstep(0.9,1,...)` 门限在球体接近静止梁时留下了生硬的块状历史边界。反之，完全无条件的平移会拖拽静止接触阴影，因此在分母中保留静态贡献。保留现有的法线运动与几何守卫。保持双线性历史重投影：试用的双三次变体增加了闪烁与信号误差，已被移除。相机 uniform 在现有矩阵与控制向量之后追加当前和上一帧逆视图投影、速度容差及两个静态深度重投影行（总计 384 字节）。

## 半分辨率管线

### Half API

`enableSsaoHalfResolution(task: SsaoTask): SsaoHalfResolutionSettings` 是唯一的 Half 启用器。它将几何输入、深度准备、估算、降噪、运动裁剪与时间历史缩减至 `ceil(width/2) x ceil(height/2)`，然后重建出全尺寸可见性纹理。它刻意以薄/接触细节及时间分辨率换取更低的开销和内存。它不承诺 4 倍总加速：源生产者与最终上采样仍保持全分辨率。

```ts
interface SsaoHalfResolutionSettings {
    enabled: boolean;
    readonly active: boolean;
}
function enableSsaoHalfResolution(task: SsaoTask): SsaoHalfResolutionSettings;
const resolution = enableSsaoHalfResolution(ao);
resolution.enabled = false; // Full estimation and reconstruction.
```

返回的纯设置对象起始为 `{ enabled: true, active: false }`。可变的 `enabled` 请求 Half；只读的 `active` 报告有效模式。重复调用返回同一设置对象。已销毁任务或已安装另一个分辨率适配器属于错误。禁用的设置、宽度低于 320 或高度低于 224 时使用普通 Full 管线。不暴露任何新的场景所有权或原始 GPU API。不存在仅估算 Half 模式或独立的重建分辨率控制。

### Half 管线数据流与着色器

源相机投影/纵横比仍从原始全尺寸深度目标推导，包括奇数维度。一个 8x8 计算准备 Pass 在 `min(2 * smallPixel + 1, fullSize - 1)` 处采样所有输入（包括速度 Z 中的精确上一帧正视图深度），并写入：

- 原始设备深度（R32F）；
- 直接写入缩小金字塔 mip 0 的线性视图深度，因此缩小所有者设置 `depthPrepared` 并跳过其自身的拷贝派发；
- 提供的有符号法线，或当生产者未提供时，使用共享 `aoDepthNormal` 从全尺寸深度一次性重建的视图法线（优于从抽稀网格重建，且省去了后续每个阶段的深度法线重建）；
- 可选的归一化速度。

拷贝保留源精度而非加宽它：法线仅对 RGBA32F 源使用 RGBA32F，其他情况使用 RGBA16F（包括重建法线）；速度对 `rg16float`/`rgba16float` 源使用 RGBA16F，其他情况使用 RGBA32F。[时间 GPU 接口与绑定布局](#时间-gpu-接口与绑定布局)中的时间容差遵循缩小后的速度格式。源附件保持借用且绝不销毁。

缩小的 `SsaoGpu` 使用 `float` 种类、始终提供的视图空间法线（仅当生产者提供世界法线时为世界空间）及其自身的半尺寸深度金字塔、AO 与边缘缓冲区。其公共 `outputTexture` 为全尺寸 RGBA16F。`sourceVelocity` 指向缩小速度视图；时间校验仍检查原始生产者的全尺寸目标，而实际滤波器采样缩小视图。所有时间纹理均从缩小 GPU 所有者推导其维度。采样足迹针对现有响应守卫标记为稀疏。

标准任务顺序变为：准备滤波器 -> 上传参数 -> 分辨率前处理（before） -> 滤波器执行 -> 可选分辨率后处理（after）。前处理回调拷贝几何并执行常规的缩小估算器/空间解析。后处理回调在经过滤波的半尺寸可见性上运行专用的 Half 管线联合双边上采样器（`ssaoHalfUpsampleWGSL`），使用独立的 176 字节全尺寸参数缓冲区。这避免了在昂贵的时间工作之前执行上采样。禁用时间滤波时，同一后处理回调对缩小的空间结果执行上采样。

准备绑定组：0 = 全尺寸 AO 参数 uniform，1 = 全深度，2/5 = 可选法线输入 / 缩小法线输出，3/6 = 可选速度输入/输出，4 = 缩小原始深度输出（R32F），7 = 缩小线性深度 mip 0（R32F）。工作组为 8x8；奇数末尾采样钳制到真实源边缘。

上采样绑定：0 = 全尺寸参数，1 = 全深度，2 = 提供的全法线（重建时缺席），3 = 稀疏可见性，4 = RGBA16F 输出，5 = 缩小原始深度，6 = 缩小法线；override `SOURCE_WORLD` 选择稀疏法线的世界到视图旋转。缩小输入已经保有每个稀疏抽头的精确全尺寸采样，因此抽头绝不重新读取或重新推导全尺寸数据。每个 8x8 组先用抽头位置、可见性与法线填充一个 6x6 工作组缓存（原点 `group * 4 - 1`，按未钳制抽头坐标索引，保存钳制抽头的数据）；接收体随后从该缓存读取它们的四个双线性抽头。接收体法线来自提供的纹理，或来自馈送给 `aoDepthNormal` 的 12x12 全深度工作组图块（原点 `group * 8 - 2`）。法线一致性通常必须达到 0.9；切平面权重使用 `max(1e-4,min(z*0.005,radius*0.025))` 加上 `0.5*length(deltaPosition)*length(deltaNormal)` 曲率余量。法线权重使用反复平方而非 `pow(x,8)`。如果四个双线性抽头的总权重低于 `1e-6`，则搜索以最近邻为中心的 3x3 邻域，按兼容性除以 `1+distanceSquared` 加权。没有兼容支持时产生中性可见性；背景保持白色。奇数尾部像素使用其实际钳制的源位置。工作组屏障位于边界/背景返回之前，使部分工作组与奇数图像边缘保持合法。

在凹接触处，标量 AO 场可以在尖锐的法线折痕上保持连续。上采样器不得仅因法线一致性低于 0.9 就拒绝相邻的墙/地抽头：交替的 Half 网格覆盖否则会在相机旋转期间使被接受的支持突然跳变。仅当法线不相对（点积大于 -0.9）、源点位于接收体平面前方且接收体位于源平面前方（有符号平面容差 `max(1e-4, viewZ*1e-5)`），且它们的世界距离间隔同时在四分之一 AO 半径以及按表面前缩调整后的 2.5 个投影像素（入射角下限 0.1）之内时，才允许该抽头。这在相连的凹折痕处恢复了原有的双线性支持，并非额外的模糊 Pass。凸轮廓、相对面与分离深度层保留拒绝；共面重建及其平面权重不变。

### Half 管线生命周期与隔离

任务拥有缩小 GPU 与公共全尺寸输出。分辨率适配器仅拥有缩小输入纹理、其全尺寸参数缓冲区以及缓存的准备/上采样绑定。设备、维度、提供法线格式或可用性以及速度格式或可用性的变更会替换这些资源并重置时间历史。替换源视图会重新绑定准备阶段并重置历史。未变更帧不创建纹理、视图、绑定组或管线。销毁是幂等的，且保持借用的生产者附件存活。

新模块仅由其启用器导入；未使用的场景不保留任何着色器、输入纹理或管线。通用任务仅支付一个可选的 `after` 调用开销。Uniform 写入器接受其精确的参数缓冲区状态，允许无需假 GPU 所有者即可复用。

公共渲染目标对象保持稳定；设备/尺寸/模式/输入可用性变更可能会替换其底层纹理，与其他 AO 资源替换相同。采样消费方必须跟随输出变更通知或重新录制其帧图。

## 真实光照演示

`demo-ambient-occlusion.html` 独占使用高级别根导出。BRDF LUT 通过 `demoAssetUrl` 相对于打包模块解析，而非从站点根路径解析，从而使 `/lite-demos/` 下的独立部署无需 lab 服务器的根资源路由即可工作。单演示调试构建同样刷新生成的画廊并拷贝其可用缩略图。AO 画廊缩略图托管于 BabylonJS/Assets，并通过 `demos-config.json` 中的 `thumbnailUrl` 固定到不可变提交 URL。独立画廊、lab 的 Demos 标签页以及 `/pages/` 开发预览会对该可选覆写进行 HTML 转义，并为没有它的演示保留现有的本地 JPG 路径。新增画廊图片应存放在 Assets。场景 355 同样使用 Assets 中固定到提交版本的 JPEG，并通过 `scene-config.json` 的 `thumbnailUrl` 指定。共享场景卡片在源码、打包、性能和兼容性网格中使用经 HTML 转义的自定义地址，其余场景继续使用各自体验页面的相对本地 JPG 路径。场景 355 用于一致性测试对照的 PNG 仍单独保留。

**Direct light** 开关添加一个方向光以演示 AO 不衰减直接光照。其运行时强度更改使用 `setLightIntensity` 以使共享灯光 UBO 失效。它在仅显示 AO 视图中没有可见效果，因为该视图显示的是可见性而非场景光照。程序化房间包含地面、两面墙、相接触的盒子、一个球体以及一个薄遮蔽体。加载的环境提供漫反射 IBL，并带有独立可切换的方向光以及用于光照隔离的自发光材质。单采样几何前置 Pass 生成有符号视图法线与深度；AO 任务在常规前向 PBR 颜色 Pass 之前消费两者。演示标明 XeGTAO 为其估算器。控件可开关 AO 或直接光；调整半径与强度；以及按需单独显示 AO。默认勾选的 **Use normal texture** 复选框选择几何 Pass 的有符号视图法线附件。取消勾选会赋值 `ao.normalTexture = null`，使估算、时间重建/传输、最终历史捕获与稀疏上采样全部从现有深度附件重建法线。状态栏标明所选法线来源。这是 AO 输入对比，并非移除演示的几何 Pass：它仍生成速度并保持其法线附件可供切回。它不会禁用法线历史或生产防鬼影保护措施。**AO quality** 选择器独立于分辨率选择器暴露 Low/Medium/High/Ultra 空间采样。默认为 High（每评估像素 18 个采样）。时间滤波默认启用，使用 API 的 16 采样历史上限。**Advanced temporal settings** 折叠区包含一个 **History sample limit** 滑块，将 `SsaoTemporalSettings.historySamples` 设为 1 到 16，并显示该上限以及作为最大历史权重的 `1 - 1 / historySamples`。因此初始最大历史权重为 0.9375（93.75% 历史，6.25% 当前 AO）；1 个采样意味着零时间历史权重。这是一个上限，而非固定混合因子：历史年龄/有效性、拒绝以及被传输足迹限制均可能提高当前帧贡献。着色器使用当前权重 `max(1 / count, 1 / blendLimit)`。采样上限变更在重新收敛前重置时间历史。当时间滤波关闭时该滑块禁用，并保留其值供重新启用。`historySamples` 绝非逐帧空间采样数。独立的时间开关与移动球体开关用于演示收敛与刚体运动处理。默认勾选的 **Motion-mask pruning** 复选框启用可选的传输优化，并允许在不重置时间历史的情况下进行实时对比。仅 AO 视图是可见性目标的拷贝，绝非最终光照图像相乘。

一个自包含的程序化 glTF 添加了一根绿色四影响骨骼蒙皮梁以及一根紫色变形目标梁。它复用了来自 scene231 的共享细分梁几何体、携带其自身嵌入式缓冲区和动画，并在场景代码中使用公共加载器/动画 API 而非原始 GPU 句柄。共享的左手坐标系梁索引在编码 glTF 逆时针三角形时一次性反转；其外向法线与共享源几何体保持不变。两个示例均保持背面剔除启用。**Skin/morph animation** 起始为勾选状态并可暂停/恢复两个示例。几何速度包含上一帧形变及可选上一帧视图深度，使同一数据也能服务于其他时间算法。常规实时演示保持这些动画启用。

### 按需启用降分辨率渲染

演示的 Full/Half 选择器控制单一的 [`enableSsaoHalfResolution`](#半分辨率管线) 模式。Half 同时缩减估算与时间重建（包括几何输入和运动裁剪），且为默认选中。场景与公共 AO 输出保持全尺寸。其状态栏区分实际激活的 Half 与小视口下的 Full 保底保护。切换 Full/Half 会替换私有所有者并重置历史；PBR 绑定跟随新的输出代次。当分辨率或法线输入模式变更时，演示重新录制 AO 任务及其仅 AO 拷贝，从而使预录制的拷贝绝不采样已退役的输出代次。

AO 参数槽 17 中的降信号（reduced-signal）标记将投影足迹低于 16 个工作像素的已传输历史限制为两次观测。Full 模式保持该标记为零。两种模式下适用相同的 RGBA 上一帧深度速度契约。

GPU 计时开关在此诊断演示中默认启用。它使用现有的根 API `setRenderTaskGpuTimingEnabled` 与 `getRenderTaskGpuTimings`，而非 CPU 挂钟测量或新的 SSAO 插桩。读数每秒最多更新四次，取每个显示间隔内新近完成的 GPU 时间戳快照的均值。采样在不执行逐帧 DOM 更新或逐帧容器分配的情况下累积。这使小于单次浏览器时间戳增量的差异在多帧累计下变得可见。它按执行顺序列出活跃的帧图任务及其测得的耗时总和（毫秒）。SSAO 任务包含所有活跃的估算与降噪 Pass；任务耗时总和并不作为独立测量的完整帧间隔呈现。禁用、等待中、不支持、回读错误及已丢弃任务状态均明确显示。不支持的设备会禁用该开关且不以 CPU 计时替代。禁用性能分析会释放现有分析器的 GPU 资源。节流后的 DOM 更新共享演示现有的渲染前回调；不增加独立的动画循环或定时器。

GPU 时间戳未针对 GPU 核心或显存频率归一化。禁用时间滤波会降低工作负载并可能导致驱动降频 VRAM；重新启用它不一定立即恢复先前的显存频率。在一次捕获的 NVIDIA 关/开序列中，显存从 7001 MHz（P3）降至 810 MHz（P5）。SSAO 从约 0.6 ms 升至 2.6 ms，几何与光照也随之变慢。恢复到 7001 MHz 后，无需再次切换时间开关即恢复至约 0.6 ms。Pass 拓扑、视口与时间控件均未变更。

在将切换后的耗时变化归因于资源保留或额外 Pass 之前，请先将耗时对比与**核心及显存频率**关联起来。WebGPU 的适配器 `powerPreference` 不会锁定任一频率。为获得可复现的性能分析，一致的逐应用驱动电源策略（例如 NVIDIA 的 **Prefer maximum performance**）可以避免这种功耗状态波动。引擎不得更改系统电源设置、运行哑 GPU 工作来维持高频率，或隐藏较慢的测量结果。

## 测试规范

### 场景 348 Babylon.js 对比

`scene348` 渲染[托管在 BabylonJS/Assets 中的 Diligent Kitchen](https://github.com/BabylonJS/Assets/tree/master/meshes/DiligentKitchen)，在白色、粗糙、非金属 PBR 基础上使用原始顶点颜色。它仅由 `environment.env` 照明，因为 `enablePbrSsao` 仅遮蔽环境光照而非直接光。Lite 运行非 MSAA 几何 Pass、带默认时间滤波的 XeGTAO（`radius` 0.3、`quality` "medium"）、`enableSsaoHalfResolution` 与 `enablePbrSsao`。Babylon.js 参考使用与最终颜色相乘的 `SSAO2RenderingPipeline`（`radius` 0.25、`totalStrength` 1.5、16 个采样）；这些数值使与 Lite 的差异最小化。两者均清除为黑色，因为 SSAO2 会将清除色乘以零背景可见性。

初始化逻辑可能在首几帧的一个与时序相关的帧上重建缩小 AO 所有者并重置历史。因此 Lite 页面在第 16 帧调用 `resetSsaoTemporal`，并在 128 帧后停止其渲染循环；参考页面在 128 帧后停止。时间累积与呈现帧由此成为确定性的；`?interactive` 保持渲染以供人工检查。测试规范还会等待 lab 加载遮罩层分离后再截图。SSAO2 从 `Math.random` 生成其半球与噪声，因此参考页面在创建管线时为其设定种子。两个页面的重复捕获均逐比特一致。打包测量使用在注册、首帧渲染及其 GPU 提交完成后发出的独立 `bundleReady` 信号。此时这个静态场景中所有与体积相关的代码路径都已加载；视觉稳定阶段不会加载额外的运行时模块。普通的 `ready` 信号仍等待第 144 帧，并继续作为一致性/截图契约。测量维持其常规 50 秒预算，并拒绝报告的错误或缺失的就绪信号。这既不改变 177 KiB 上限，也不改变渲染或参考像素。场景打包测量在 CI 或 `--software` 下显式选择 Dawn 的软件适配器，并在测量前检查其架构为 `swiftshader`。Linux 同样保留其用于外部图像互操作的 ANGLE/Vulkan 软件合成器标志。默认的 BRDF 图像上传在测量场景前进行校验，而不是假定仅枚举适配器就一定能保证上传路径可用。

无 AO 时两个渲染的全图 MAD 差异为 1.1。由于 AO 算法与合成方式不同（Lite 在色调映射前遮蔽漫反射 IBL；SSAO2 压暗色调映射后的颜色），实测 MAD 为 5.26（全分辨率、高质量 AO 时为 4.95），上限为 7：这是光照、几何与遮蔽位置的粗略界限，而非等价性声明。
