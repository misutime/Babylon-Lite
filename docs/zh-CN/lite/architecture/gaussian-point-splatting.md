# 模块：高斯点泼溅（Gaussian Point Splatting）

> 包路径：`packages/babylon-lite/src/gaussian-point-splatting/`

## 目的

面向静态泼溅网格（含球谐函数 SH）与流式泼溅的可选随机高斯渲染。所有集成均属于此目录：经典网格、加载器和管线构建器不包含任何点渲染器元数据或分支。在不启用此特性的情况下导入根包，必须为无关场景增加恰好零字节的运行时开销。

## 公共 API 接口

根包导出 `enableGaussianPointSplatting(scene, target, options?)` 和 `disableGaussianPointSplatting(scene, handle)`。目标为 `GaussianSplattingMesh | GaussianSplatStream`；返回的 `GaussianPointSplatting` 是一个可变纯状态对象，包含：

- `colorRenderMode: boolean`（默认 `true`）。
- `depthRenderMode: boolean`（默认 `false`）。
- `depthVisualization: "none" | "linear" | "alphaBlended"`（默认 `"none"`）。这是 `gsLinearDepthFragment` / `gsAlphaBlendedDepthFragment` 的点路径等效项。调用方必须将其设置得与应用于经典网格的片段保持一致。启用 `depthRenderMode` 时显示深度可视化；不执行任何片段内省。`linear` 以全分辨率渲染不透明圆盘，独立于点密度、渲染缩放除数和累积随机覆盖率。`alphaBlended` 保留随机采样及其预乘深度均值。
- `pointScale: number`（默认 `1`，有限且非负）。
- `renderScale: number | "auto"`（默认 `"auto"`；整数除数 1–8）。
- `occlusionCulling: boolean`（默认 `false`）。
- `maxAccumFrames: number`（默认 `255`，整数 1–65535）。累积收敛并停止点计算后的每像素采样数；合成阶段持续呈现已收敛的图像。混合不透明场景继续监控可见性，但不推进进度或回读。修改该值从不丢弃已有采样：增大它会恢复细化，减小它会更早停止。
- `temporalReprojection: boolean`（默认 `false`，实验性，仅限 Lite）。世界/视图/投影变化会将累积重映射到新视图，而非硬重置它，从而将采样噪声限制在去遮挡区域和屏幕边缘。参见下文的 _时间重投影_。
- 只读属性 `progress`，渲染前和销毁后为 null，否则为 `{ renderedFrameCount, accumulatedSamples, accumulationVersion, pixelCycleLength }`。`renderedFrameCount` 统计自上次累积重置以来已派发的帧数，并在收敛后停止增长；`accumulatedSamples` 是已完成的每像素采样数，在 `maxAccumFrames` 处饱和。保持相位的刷新在达到该采样上限后最多可能需要额外一个部分周期才停止派发，以便每个周期槽都能处理变化后的内容。

`GaussianPointSplattingOptions` 是可变设置的可选部分形式。重复调用启用函数会在校验选项后更新现有句柄。同一目标不能同时在两个场景中启用。

Trogir 流式示例在其 HUD 中暴露了此状态。点采样默认关闭（`?points=1` 可在启动时默认开启）；首次激活创建一个句柄，后续切换则修改 `colorRenderMode` 并保留其 GPU 资源。仅在启用时可见的控件可调整密度、渲染缩放除数（标签 1、1/2、1/3、1/4 分别映射到值 1、2、3、4）、遮挡剔除、实验性时间重投影（`?reproject=1` 可在启动时默认开启）以及累积上限。只读进度显示已累积采样数与上限（`X / max`）以及像素周期长度。常驻可见的 FPS/帧时间计数器对现有帧钩子的时间差求至少 500 ms 的平均值。HUD 销毁时在流/场景销毁前禁用该句柄。该示例根据引擎的保证缓冲区限制除以每全分辨率累积像素 16 字节来约束其画布后备存储面积。布局/DPR 观察器在渲染回调之外（包括 CSS 调整大小、浏览器缩放和显示器变更后）更新 `maxDevicePixelRatio` 并调整表面尺寸。此上限独立于点渲染缩放除数，并同样约束可选的重投影历史缓冲区。激活失败时会取消勾选复选框、隐藏点控件并显示状态消息，而不会停止经典渲染器或触发启动失败覆盖层。

## 内部架构

`gps-suppression.ts` 拥有一个由已启用句柄共享的懒初始化逐场景跟踪器。它在启用时及每帧之前扫描 `scene._renderables`，包括由延迟注册产生的可渲染对象，并排除点可渲染对象。对于静态目标，order 为 200 的透明可渲染对象是候选项。对于流，现有的 `stream._renderable` 直接标识候选项。

每个候选项的 `bind` 会被包装，而不改变其批次列表、管线或绑定接收者。其 `draw` 接收一个转发 Proxy，按渲染通道或渲染包编码器进行缓存。所有原生编码器方法均以真实编码器作为 `this` 调用。

被拦截的 `setVertexBuffer` 通过 GPUBuffer 标识识别静态目标：基础经典管线和 SH 经典管线都会绑定 `mesh._gs._splatIndexBuffer`。普通 PLY/splat、SOG、SPZ 和 glTF 泼溅使用 `attachParsedSplat`；过程式泼溅直接附加同一基础经典管线。因此两条路径都不需要网格反向链接。即使关闭颜色渲染，发现机制仍会运行。一旦识别出目标，仅当其 `colorRenderMode` 启用时，才会吞掉 `draw`、`drawIndexed`、`drawIndirect` 和 `drawIndexedIndirect`。所有绑定侧通知以及流选择/规范收集工作仍正常执行。在流的引导绘制通知之后，其共享批次的 `queue` 包装器在点颜色激活期间替换为上一次已完成的投影键。因此现有批次可以收集发生变化的规范记录，而无需重复经典投影、压缩或基数排序。引导投影/回读与绘制通知正常运行；关闭颜色模式会重新排队真实键，从而在经典绘制前对变更的内容或视图进行排序。

对于静态网格，经典更新持续运行直至首次排序完成以保留 `firstSortReady`，随后在点颜色激活期间暂停。这避免了工作线程排序和排序结果上传。重新激活经典渲染时，待处理的顺序会被回收而不上传，并排空现有的双缓冲区工作线程池。下一次经典更新强制执行一次全新排序；经典绘制保持门控直到该结果上传完成。后续相机运动采用正常的异步经典排序策略，因此持续移动不会无限期延迟重新激活。此门控在特性销毁后依然有效：恢复经典 `bind` 会等待全新的排序。所有这些策略均位于可选的抑制模块中，不会向经典加载器或网格管线添加任何特性导入、元数据或分支。被抑制的绑定报告零次绘制调用。

若观察到一次绘制没有匹配的缓冲区，则表明其为非目标候选项。其原始 `bind` 会被恢复，缓存的包装器变为透传空操作，并递增 `scene._renderableVersion`。被拒绝的候选项不会在每帧被重新包装；启用另一个目标时会重置该拒绝缓存。禁用会恢复自有的包装器（包括缓存的绑定），并在最后一个句柄移除时移除扫描钩子。

## 管线配置

该特性拥有用于预处理、分块/汇总前缀扫描、扫描加法、分区、随机采样、解析（resolve）以及可选 Hi-Z 的计算管线。计算和合成变体保存在一个懒初始化的 `WeakMap<GPUDevice, DeviceCache>` 中，使交替使用的引擎在预热后复用各自的管线，而不在导入时保留未使用的设备或分配缓存。合成阶段是一个带有预乘 Alpha 混合、无条件合成深度比较、可选几何深度写入以及目标多重采样数的全屏三角形。颜色模式或带有非 `none` 显式深度可视化的深度模式下会启用颜色写入。

泼溅工作缓冲区将活动计数与容量分开跟踪。它们在容量范围内的减增过程中保留其分配和计算绑定组，在需要时按几何级数增长（受设备缓冲区限制约束），并在提交后退役被替换的缓冲区。分配大小使用容量；uniform、扫描长度和派发工作组仅使用活动计数。

共享的 `Params` uniform 为 80 个浮点数 / 320 字节。前 76 个浮点数保留现有的矩阵、分辨率、采样、代数和可视化布局。最后一个 vec4 为 `(historySampleIndex, historySamples, viewportX, viewportY)`。每个原生采样点拥有独立的全分辨率颜色/深度/计数/原生深度缓冲区，按 `y * width + x` 索引。独立平面在默认存储绑定限制下保留了原始单采样最大尺寸；四个采样点绝不能要求四倍大的单块绑定。解析和监控使用各自独立的 320 字节参数缓冲区逐平面处理。解析阶段为较早的平面加载共享点键，并仅在最后一个平面中清除它们。合成阶段为每个平面绑定一对颜色/深度缓冲区（四个采样点对应八个存储绑定），并通过 `sample_index` 选择对应的一对。纯泼溅随机视图在各目标采样点之间共享同一份历史；混合视图和确定性圆盘光栅化保留每个原生采样点。

## 着色器逻辑

预处理读取静态中心/协方差/颜色纹理及可选 SH 纹理，或流的 64 字节规范记录。它投影协方差、计算泊松采样数，并存储一条 64 字节屏幕记录。前缀扫描和一个 65537 项的分区表将点索引映射到高斯体。采样阶段按像素原子性地选择最近深度/RGB565 键。解析阶段清除这些键并更新带代数标记的运行颜色均值和深度。合成阶段显示累积颜色或显式的线性/Alpha 混合深度模式。着色器定义与 SH 阶数特化位于 `gps-shaders.ts`。

点计数缓冲区包含两个 `u32` 字：总点数以及流的最大采样辐射度（radiance）的正浮点数位模式。每次流式预处理清除第二个字，然后原子性地归约其采样屏幕记录的最大非负 RGB 分量。采样阶段除以该最大值与静态辐射度缩放（1，静态 SH 为 8）中的较大者；解析阶段乘以完全相同的缩放因子。因此 RGB565 量化在平均覆盖率之前不会截断流式 HDR 颜色，且即使缩放发生变化，每帧累积依然保持在辐射度单位中。

深度可视化从全部四个 Z/W 投影系数重建视图深度：`(P32 - z * P33) / (z * P23 - P22)`。在存储的反向 Z 深度、1 和 0 处求值分别得到表面深度、近平面和远平面，因此线性和 Alpha 混合灰度同时支持透视和正交静态相机。Alpha 混合解析在求平均前将每个可视化采样转换为线性深度，并将预乘灰度存储在现有的颜色历史中；几何深度仍单独保留用于深度写入/重投影。非 Alpha 混合的线性解析则如下文所述以全覆盖率显示最近确定性圆盘的深度。可视化相机变化会重置历史，而非重投影依赖深度的灰度。

可见性使用消费任务的实际深度附件，而非使用不同采样数或深度/模板格式重放几何体。特性自有的任务/编码器适配器将点计算推迟到原生通道中到达点绑定的时刻。它结束该通道，采样其仅深度视图，并以 `load` 恢复颜色/深度/模板附件，同时恢复动态视口/裁剪/模板/混合状态和场景绑定组。原生几何体仅执行一次。因此原生的 alpha-to-coverage、模板写入/测试顺序、合并的 ShaderMaterial 几何体、薄实例 LOD 以及从早期共享/急切任务加载的深度均完好保留。该适配器以真实接收者转发所有原生方法，并与透射（transmission）现有的拆分通道协同工作；在最后一个句柄销毁时移除。它临时插桩命令编码器的 `beginRenderPass` 方法，绝不改变命令编码器的对象身份，因此提交围栏（fence）和回读仍然匹配。原始方法描述符在 `finally` 中恢复；现有的 GPU 计时插桩仍保留在调用链中。新增/替换的任务在渲染前和构建点绑定时被发现。被取代、移除和销毁的包装器会被停用，因此保留了已捕获包装器的其他特性无法让点插桩继续存活。最后一个句柄的释放具有幂等性。每个保留的句柄提供一个实时渲染模式谓词。当没有任何保留句柄启用颜色或深度渲染时，任务包装器直接调用原生执行函数：编码器方法保持原样，不创建任何通道代理或转发状态。重新开启句柄会在其下一次执行时恢复通道插桩，而不会丢弃缓存的 GPU 资源或改变经典全新排序恢复行为。

适配器跟踪实际的前置绘制命令，包括透明深度写入者和早期的点绘制。未知渲染包保守地计为潜在深度贡献者；只有任务中具有空不透明绑定列表的原生不透明渲染包才被证明为空。深度清除会重置该证据；LOAD 段则保留它。即使当前任务中没有任何前置绘制，已加载的共享/急切深度仍是有效的深度源。透明度、缺失网格反向链接、管线标签和绘制顺序绝不能证明原生绘制不会写入深度。准备阶段在暂停原生通道之前检查收敛状态，因此未变更且无需监控的纯点视图可以直接合成，无需额外的通道边界或解析。

混合 MSAA 可见性为每个消费通道采样点保留独立的颜色/深度/计数/上一帧深度历史。解析阶段在求平均前将当前随机命中与每个原生深度采样进行比较；合成阶段使用 `sample_index` 选择该采样点的历史。将覆盖率平均到单个像素 Alpha 中会错误地使不透明前景变暗，因此绝不允许这样做。相机视口偏移寻址原始全尺寸深度纹理。每个平面在分配前都会对照设备限制进行检查，而不降低原生采样覆盖率。无相机或空有效视口会在录制前被拒绝；恢复资格时会重置累积。上一帧深度历史检测逐采样点的遮挡物变化并清除受影响的历史，包括当前帧未采样的周期像素。收敛后可见性仍继续检查；未变化的已收敛像素保持冻结，而变化的像素独立恢复。即使已收敛的帧进度保持冻结，采样种子仍继续推进抖动周期。监控器将剩余工作归约到一个 GPU 标志并生成间接派发参数：字 1–3 为预处理/分块扫描/扫描加法参数，4–6 为扫描汇总参数，7–9 为分区参数，每个 Hi-Z 层级从字 10 开始占用三个参数。层级 0 同时驱动解析。未变化的已收敛视图对这些阶段和随机采样派发零个工作组；仅执行廉价的原生深度监控和合成。这也自然处理了无网格的原生 HDR/DDS 背景，而无需猜测某个可渲染对象是否写入深度。深度变化会重置受影响采样点的历史并唤醒处理，直到该采样点独立达到累积上限。纯泼溅场景保留其原有的收敛后跳过派发行为，且不分配任何不透明深度资源。

Hi-Z 绝不从随机泼溅命中派生。对于受支持的反向 Z 不透明通道，一个专用的计算通道将当前不透明纹理归约为每个全分辨率像素块中的最远视图深度（未覆盖像素贡献无穷大），随后在预处理之前构建最大深度层级。若没有保守的不透明深度源，或对于其他深度比较约定，则禁用剔除而不是使半透明/背景采样产生偏差。

非 Alpha 混合的 `linear` 可视化在完整输出分辨率下使用单独的确定性仅深度圆盘光栅化。预处理保留每个有效泼溅，独立于点密度/泊松采样和原生 Hi-Z。可重用的圆盘缓存必须包含当前隐藏在移动遮挡物背后的几何体。深度纹理和光栅化管线使用消费通道的采样数。圆盘支集为 `delta^T inverseCovariance delta <= 2 * opacity`；存活片元为不透明，反向 Z 深度测试选择最近的圆盘。一个解析变体直接将该深度纹理读取为不透明线性深度输出，不经过时间平均。`alphaBlended` 保留随机预乘深度均值。线性圆盘深度使用未量化的投影中心深度，该模式将其存储在原本未使用的屏幕 RGB 字段中。未变化的确定性视图在首次圆盘光栅化后即完成，独立于 `maxAccumFrames`。其原始圆盘有效性键包含尺寸、采样数、世界/视图/投影矩阵、流式内容代数和静态数据版本，独立于累积/可见性键。添加或移除最后一个原生贡献者会重置可见性历史，而不会使未变化的原始圆盘失效。当仍需监控不透明可见性时，重用已完成的圆盘纹理并仅运行可见性解析；不要对未变化的圆盘重复预处理或光栅化。初始为空的流在线性模式下仍会清除缓存的深度纹理并解析出透明输出，但不创建光栅化绑定组或发出圆盘绘制。其零容量屏幕缓冲区无法满足着色器最小 64 字节 `Screen` 绑定的要求。发布非空内容会使完成状态失效、扩充工作缓冲区，并执行首次有效圆盘光栅化。

## 状态机 / 生命周期

每个目标/签名拥有视图状态和 GPU 缓冲区。代数键包含使之失效的选项（除 `maxAccumFrames` 之外的所有选项，包括深度可视化）、静态目标数据版本、世界/视图/投影矩阵、尺寸以及有效渲染缩放。任何变化都会硬重置累积。静态 `updateData` 会被包装以递增特性自有的内容版本，并在禁用时恢复。

在静止相机下流式内容刷新则执行软重置：帧计数器被钳制到 `min(GPS_SOFT_RESET_SAMPLES (8), maxAccumFrames - 1)` 个采样，同时保留亚像素抖动相位。每次刷新还要求在收敛停止派发之前至少完成一个完整的 `n²` 帧周期，包括在部分周期期间发生的刷新以及上限为 1 个采样的情况。在整个刷新周期内禁用 Hi-Z 拒绝；在每个后续符合条件的预处理通道之前都会构建当前的原生不透明层级。解析阶段将每个像素的运行均值计数钳制到上传的历史上限（最多为 `maxAccumFrames - 1`，允许为零），使新进采样绝不会超过上限，且新 LOD 能够平滑混入而不会使环境天空等稀疏内容变黑闪烁。如果流推迟了其规范收集（`gatheredGeneration !== contentGeneration`），该帧跳过点计算，屏幕上保留上一帧累积。自动渲染缩放会立即增大（变粗），但仅当 `sqrt(points/budget)` 降到当前除数的 1.25 倍以下时才细化，从而避免带噪声的点数回读在几帧内来回翻转并重置累积。一旦 `floor(frames / cycle) >= maxAccumFrames` 且待处理的刷新周期已完成，则跳过计算派发和回读。流规范收集批次仍排在点计算之前。资源在提交后退役；忙状态下的异步回读在其映射完成后进行清理。

### 时间重投影（实验性）

着色器和通道位于 `gps-reproject.ts` 中，仅在首次使用时动态导入，因此关闭该选项的场景不会加载它们。在模块到达之前，视图变更仍会重新启动累积。

即使启用了重投影，受原生深度监控的视图在世界/视图/投影变化时仍保守地执行硬重置。重投影一个已经混合过的历史无法安全地逐采样测试其与原生几何体的遮挡关系：将目标移动到未变化的遮挡物后方绝不能保留其前景颜色。原有的单历史重投影路径仍可用于纯泼溅颜色视图。

启用 `temporalReprojection` 时，世界/视图/投影矩阵会移出代数键并单独跟踪。当它们变化时，`prepare()` 根据上一帧矩阵构建 `M = P·V·W · (P'·V'·W')⁻¹` 及其逆矩阵。懒加载模块在 52 浮点数、208 字节 uniform 的浮点偏移 0 和 16 处打包这两个列主序矩阵，随后在偏移 32 处打包当前逆投影矩阵。`(width, height, generation, history cap)` 紧随其后位于偏移 48。如果任何逆矩阵奇异或非有限，累积会硬重置。完整逆投影矩阵通过 `(P⁻¹ · clip).z / (P⁻¹ · clip).w` 重建正的有限当前视图深度，无需从帧间变换的齐次尺度推断深度，即可支持透视（有限或无限远平面）、正交以及离轴投影。在预处理之前，`record()` 执行：

1. 将累积、深度和计数复制到懒分配的历史缓冲区（每个全分辨率像素约额外 32 字节），并清除两个散射目标。
2. 将每个有效上一帧像素（当前代数、非零计数、处于 `(0, 1]` 内的正深度）从其像素中心和存储的 NDC 深度通过 `M` 散射。拒绝非正/非有限 W、越界投影 Z 以及非正/非有限重建视图深度。使用 `atomicMax(bits(zc))` 为每个目标像素保留最近的当前反向 Z 投影深度 `zc = clip.z / clip.w`；正浮点数位模式保持反向 Z 序。
3. 记录每个目标像素的胜出源像素。这些散射通道仅用于估计当前深度；它们不再决定从何处采样历史颜色。
4. 拉取聚集（Pull gather）：选择胜出者作为深度源。当八个邻域中至少有六个像素的重建当前视图深度更近超过 10% 时，该像素属于放大表面中的裂缝，改选最近邻域的源。空像素选择最远邻域的源，因为去遮挡通常暴露背景。近/远邻域选择使用重建视图深度，而非齐次 W 或原始投影深度比。没有任何源的像素获得零颜色/深度和 `generation << 16`（零采样），从而保留解析阶段的临时空洞填充。
5. 通过 `M` 重投影所选源以获取 `zc = clip.z / clip.w` 并重建其当前视图深度 `vc`。构造目标像素精确的像素中心 NDC 点 `((d + 0.5) / size * 2 - 1)`，取反 Y 并将 Z 设为 `zc`，然后通过 `M⁻¹` 变换并除以 W。上一帧的浮点像素坐标为 `(previousNdc.xy * (0.5, -0.5) + 0.5) * size - 0.5`，因此整数代表像素中心。这种反向映射保留了亚像素运动，而不会冻结在取整后的散射目标上。
6. 在该坐标周围双线性采样四个历史抽头（tap）。抽头必须在边界内、具有当前代数、正计数和正深度，并且具有有效的投影/当前视图深度且与估计深度一致：`abs(viewDepth(reprojectedTap) - vc) <= 0.05 * vc`。5% 的相对视图深度容差在允许局部微小深度变化的同时拒绝不同表面。将双线性权重乘以抽头有效性并重新归一化。计数取正权重已接受抽头中的最小计数，并钳制到 `min(GPS_REPROJECTION_SAMPLES (16), maxAccumFrames - 1)`（至少为 1）。如果总权重低于 `1e-4` 或反向变换的 W 无效，则改用复制所选源的颜色/计数。裂缝/空洞邻域填充将结果计数减半，最小为 1。将 `clamp(zc, 0, 1)` 存储为深度。聚集阶段仍然只绑定八个存储缓冲区；不需要额外存储。

帧计数器被软重置为相同的采样上限以恢复累积，并且在收敛前必须完成一个完整的像素周期，即使运动发生在上一周期中途也是如此。在该整个刷新周期内跳过遮挡剔除，并仅从当前不透明深度恢复。在接下来的 `n²` 个已派发帧中，解析阶段使用填充模式（`state.z = 2`，对比硬重置的 `1` 和正常累积的 `0`）。现有的计数缓冲区充当空洞掩码：当前代数中计数为零的像素在其 `n×n` 块内（周期像素除外）接收当前低分辨率点采样的颜色和深度。这些临时填充保持计数为零并每帧刷新，显示点采样噪声而非底层场景，直到每个像素的周期槽以权重 1 提供其首个真实采样。新的重投影会重启填充窗口；硬重置会清除它。不分配任何额外的掩码缓冲区。

历史缓冲区归像素缓冲区目标所有，并随其一起退役；懒初始化的重投影管线缓存以弱引用方式按设备键控。

已知限制：每像素单个深度会使半透明边缘错位，依赖视角的 SH 颜色在刷新前会被复用，反复双线性重采样可能使移动表面变柔和，且每个移动帧都需要付出复制/散射/聚集通道的带宽代价。邻域深度估计和最近回退在去遮挡边界附近仍可能产生伪影。Babylon.js 中没有对应功能。

## Babylon.js 等价映射

颜色/深度开关、随机采样密度、自动渲染缩放、累积进度以及深度可视化对应于上游点泼溅模式。经典着色器片段选择由调用方显式镜像，而不是通过添加到经典网格上的元数据来推断。

## 依赖关系

场景/可渲染对象契约、相机、引擎 GPU 退役与标志位、流式规范缓冲区/批次以及本地状态/着色器模块。没有任何通用模块导入此特性。

数值测试与硬件计算回读覆盖后向运动前景碰撞、横向运动深度拒绝、正交以及有限/无限透视投影。无视觉硬件回归测试位于 `tests/lite/integration/gaussian-point-reprojection.spec.ts`：它在 12 个像素上运行实际的三个计算通道，读取胜出源/颜色/深度/计数缓冲区，并检查视图深度 2 处的红色前景与深度 10 处的绿色背景。向后平移一个单位必须保留前景（当前视图深度 3 对 11）；横向平移尽管两个齐次尺度比均为 1 也必须拒绝背景双线性抽头。它还测试拒绝移动到相机背后或远平面之外的历史、非有限/越界的存储深度，并验证空洞填充在横向运动期间利用视图深度选择更远的邻域。该测试可通过设置 `LAB_TEST_PORT` 复用运行中的实验室服务器且需要 WebGPU；它不进行任何截图或耗时断言。实验性重投影没有 Babylon.js 对照/参考捕获；Spector 检查验证其自身的三通道布局与着色器状态，而非跨引擎像素等价性。场景 120/122/123/124/226 的过滤构建产物相对于干净代码树必须有恰好零字节的原始增量。硬件 WebGPU 冒烟检查演练基础和 SH 静态管线，不进行视觉对比或性能测量。
`tests/lite/integration/gaussian-point-sampling.spec.ts` 运行真实的流预处理、RGB565 采样、解析和合成着色器并附带缓冲区/纹理回读。它验证了针对陈旧 Hi-Z 的拒绝与未剔除刷新的对比、可增可减的逐帧 HDR 最大值、四分之一覆盖率辐射度累积（包括辐射度 2 产生 0.5）、静态基础/SH 着色器编译，以及针对近/中/远深度（近/远平面 1/11）透视和正交相机的两种深度可视化模式。交替出现的前景/背景采样验证逐采样不透明拒绝和均值线性深度可视化；遮挡物移除与进入会重置已收敛历史。一个真实的不透明渲染绑定还演练了 WebGPU 上的原生任务执行、场景 uniform、附件和纹理采样。两个共享同一个实际不透明 ShaderMaterial 的网格产生一个无网格的合并可渲染对象：其深度必须拒绝背景采样，隐藏两个数据包则必须重新显露它们。实际的薄实例 LOD 分桶发布与伙伴消费必须贡献深度，并在源、伙伴和可渲染对象版本刷新间共享同一签名。一个 300 帧的半透明红前景 / 蓝背景序列在开启和关闭保守剔除且不透明深度为空时必须产生完全一致的收敛 RGBA。两种颜色都必须保留。确定性线性深度光栅化必须覆盖按不透明度缩放的圆盘、无论提交顺序如何都选择重叠圆盘中更近的一个，并在点密度为零时正常工作；独立的 Alpha 混合用例则保留加权均值。真实的四采样原生 ShaderMaterial 任务覆盖零/部分 alpha-to-coverage、普通轮廓、模板条件深度、共享 RT 加载深度、急切外部深度、围绕点绘制的透射拆分，以及包含第 51 像素在内的分数 101 像素右半视口。真实的原生 HDR 立方体贴图天空盒配合完整点运行时必须收敛到零间接工作量、在原生深度变化时唤醒并重新收敛。在启用重投影时将目标跨过固定遮挡物移动必须重置而非保留陈旧前景颜色。四采样线性圆盘仅光栅化一次，包括初始被遮挡的几何体；隐藏该遮挡物无需重新光栅化即可显现缓存的圆盘。一个真实的流 GPU 状态在线性模式下以零个活动泼溅启动、无验证错误地解析透明输出，随后发布一个规范泼溅并解析其深度。同时关闭两种模式必须原样转发原生通道；重新激活深度模式会恢复插桩和相同输出，而不分配新的累积缓冲区。多句柄单元测试覆盖检查颜色或深度任一模式在最后一个活动句柄关闭或释放之前都会保持插桩激活。
`gaussian-point-scene-depth.test.ts` 覆盖借用原生附件所有权、渲染任务过滤、仅加载覆盖层、原生视口取整、共享持久签名标识以及缺失相机/空视口拒绝。它还验证编码器身份、原生接收者、加载描述符克隆、动态状态恢复、多原生通道段、引用计数安装、延迟/替换/移除的任务以及异常清理。运行时测试还演练恢复资格与代数重置。两个 GPU 回读测试规范在专用的无视觉 BrowserStack WebGPU CI 任务中运行，不产生截图、视频或 trace 工件。
