# MeshLoD 架构

> 运行时：`packages/babylon-lite/src/mesh-lod/` 与
> `packages/babylon-lite/src/material/pbr/pbr-mesh-lod-renderable.ts`。
> 离线转换：[MegameshCLI](https://github.com/CedricGuillemet/MegameshCLI)。

## 1. 目的

MeshLoD 是面向大型静态三角形网格的可选启用路径。原生 `mesh-lod-tool` 将每个 glTF 图元转换为确定性的 `.mlod` 层级结构。Babylon Lite 先加载其元数据与固定（pinned）粗糙页面，随后为每个实例选择驻留且无裂缝的簇（cluster）切面，按需请求更精细的页面，并为每个资产/材质批次提交一次间接绘制。这不会取代普通 glTF 加载器，也不要求未导入该特性的场景包含 MeshLoD 代码。

## 2. 支持的材质

由材质拥有的渲染器支持不透明 PBR 金属-粗糙度材质（包括无光照 unlit 和双面），以及雕像模型所使用的基础色、法线、ORM/遮挡和自发光属性。Alpha 混合/遮罩、透射、清漆、光泽（sheen）、UV2、Gamma 反照率解码、光照贴图、弯曲法线（bent normals）、电介质反射率扩展、逐纹理 UV 变换（包括材质侧 V 翻转）、逐材质环境/局部探针、材质模板状态、材质插件以及其他不支持的扩展都会以 `MLOD_UNSUPPORTED_MATERIAL` 失败，而不是静默丢弃特性。材质和场景变换由应用程序提供，不存储在 `.mlod` 中。
混合门控使用普通 PBR 的有效状态：`alphaBlend === true`，或在 Alpha 截断值缺失/非正时 `alpha < 1`。显式设置 `alphaBlend: false` 并不能使仅靠 Alpha 实现透明的材质变成不透明。注册、延迟构建以及脏材质更新都会强制执行此门控。
无论是否调用了普通材质的 `enableMaterialStencil()` 可选开启项，任何已赋值的 `stencil` 对象（包括写入者、测试者和默认状态）均不受支持。注册会在安装场景批次之前拒绝；延迟构建会在分配材质/绘制资源或获取纹理之前校验每个活动批次。脏材质更新会在 GPU 上传之前拒绝。MeshLoD 绝不能静默忽略遮罩测试或省略会影响后续绘制的模板写入。

仅支持场景的全局环境。通过 `setPbrEnvironment`、`setPbrLocalEnvironment`（盒状或球状）或 `setPbrLocalEnvironmentProbeSet` 进行的赋值都会以 `MLOD_UNSUPPORTED_MATERIAL` 失败（其 `actual` 为 `"per-material environments or local probes"`），即使存在全局环境或尚未调用 `enablePbrLocalCubemap()` 也是如此。共享校验器使用轻量级状态模块检查 `_getPbrLocalEnvironment(material) !== undefined`，而无需导入局部立方体贴图渲染器。注册、延迟构建和脏材质更新分别在场景变更、绘制分配/纹理获取以及上传之前强制执行此限制。`clearPbrLocalEnvironment(material)` 会移除赋值并恢复可用性；仅启用局部立方体贴图不会使原本受支持的材质变为无效。

MeshLoD v1 不支持使用 `useFloatingOrigin: true` 创建的引擎。场景注册与材质构建会在安装批次或分配绘制资源之前以 `MLOD_INVALID_OPTION` 拒绝该配置；绑定与更新也会强制执行此门控。CPU 与 GPU 选择都需要绝对世界变换和正常的、未重定原点的相机矩阵。

## 3. 公共 API

所有导出均来自根 `@babylonjs/lite` 入口点。一个资产拥有不可变的 `metadata`、实时的 `diagnostics` 以及共享运行时资源，但不持有任何场景引用。一个实例是引用该资产及其 `PbrMaterialProps` 的纯 `SceneNode` 状态；场景负责注册与清理。

```ts
const asset = await loadMeshLoD(engine, "/mesh-lod/model.mesh000.prim000.mlod");
const instance = createMeshLoDInstance(asset, material);
addMeshLoDToScene(scene, instance);
```

`loadMeshLoD(engine, source, options)` 接受 URL、`ArrayBuffer` 或 `Blob`。选项包括屏幕空间误差、迟滞（hysteresis）、GPU/CPU 缓存上限、请求并发度/重试次数、`"gpu"`（默认）或 `"cpu"` 选择模式、`AbortSignal` 以及请求 `fetch`/请求头/凭据。独立的 setter 可在运行时调整误差、缓存预算、流式传输暂停、调试视图和选择模式；`getMeshLoDDiagnostics` 读取实时快照。移除实例或销毁其资产使用对应的根 API。当前类型和精确签名位于 `mesh-lod.ts`。

`cloneTransformNode` 通过专门的 SceneNode 克隆钩子保留 MeshLoD 实例，包括嵌套在普通变换节点下的实例。克隆体共享资产/材质，复制可见性、误差覆写、TRS 及任何原始局部矩阵，并获得一个新的资产局部实例 ID。其变换存储与选择历史相互独立；它初始处于未注册状态，可单独添加到同一场景或另一场景中，前提是目标场景使用该资产所属的引擎。

## 4. 所有权与帧流程

```text
MegameshCLI: glTF 图元 -> 聚类层级结构 -> 打包页面 -> .mlod
loadMeshLoD: 范围数据源 -> 已校验元数据 -> 固定粗糙页面驻留
createMeshLoDInstance -> addMeshLoDToScene -> 场景拥有的批次注册表
渲染任务更新 -> MeshLoD 选择/展开批次 -> PBR 间接绘制
流式步骤 -> 请求调度器 -> 解码/上传 -> 页面驻留
```

场景注册表按精确的资产与材质标识对实例进行分组。每个批次拥有一个不透明可渲染对象。资产和实例均不反向指向场景；PBR MeshLoD 模块拥有其自身的着色器、管线、绑定组和渲染数据包。通用帧图仅通过正常可渲染对象和可选的绘制更新批次边界与该特性交互。必须在场景注册之前添加新的资产/材质批次；之后向现有批次添加实例受支持，并会在绘制前扩充其 CPU/GPU 实例容量。

跨场景共享要求引擎身份严格一致：资产的加载引擎必须等于 `scene.surface.engine`。支持同一引擎的不同表面。注册会在安装注册表、材质重建钩子、延迟构建器或实例之前以 `MLOD_INVALID_OPTION` 拒绝不同的引擎。拒绝操作不会改变两个场景以及资产的几何体、流式传输和帧退役所有权；资源绝不能迁移到第二个引擎。

## 5. 懒加载边界

公共外观支持 tree-shaking。加载与场景注册仅在使用时导入其实现，页面解码器也会懒加载。GPU 选择缓冲区在首次 GPU 模式更新时创建；CPU 选择保留作为参考实现及用于诊断视图。模块导入时不执行任何特性注册或可变缓存分配。`tests/lite/build/mesh-lod-tree-shaking.test.ts` 负责守护未使用路径。

## 6. 容器契约

版本 1 的 `.mlod` 为小端序：256 字节文件头、64 字节目录项、必需的 provenance/groups/clusters/hierarchy/page-reference/page-table/page-data 节，以及 64 KiB 对齐且最大 256 KiB 的存储页面。文件头记录源网格/图元、包围盒、计数、源摘要和构建指纹。文件头、目录、元数据和各个存储页面均带有 CRC32C 校验；必需的未知节或不兼容版本会显式失败。读取器的权威布局和校验器位于 `mesh-lod-format.ts`；写入器与转换选项在 MegameshCLI 中维护。层级节点从每级一个根节点开始；解析器在选择前拒绝环、共享子节点、不可达节点以及越界的组/页面/簇引用。
可达叶子记录还必须覆盖每一个拥有几何体的组。仅凭节点可达性无法确立这一点：将叶子重定向到另一个有效组可能会隐藏固定回退面或遗漏更精细的替换。在森林遍历校验完可达性后，引用校验会在一个组数量大小的位集中记录被覆盖的叶子组 ID；任何没有可达叶子的非空组都会以 `MLOD_INVALID_HIERARCHY` 及该组的簇计数字段偏移量失败。经 CRC 重新封装的完整文件、引导段以及公共 URL 加载回归测试在解码/分配之前同时覆盖被遗漏的固定组和被遗漏的精细组。

层级、组和簇的球心只能包含有限 float32 值，其半径必须有限且非负。元数据解析在解码或 GPU 分配之前，以 `MLOD_INVALID_HIERARCHY`、节类型以及精确字段字节偏移拒绝无效分量。零半径球体仍有效。

每个非终端组的 `simplifiedError` 必须有限且非负，包括位于未固定精细页面上的组。负值、负无穷大、正无穷大和 NaN 在完整文件和引导解析中均会以 `MLOD_INVALID_HIERARCHY`、groups 节类型以及精确误差字段字节偏移拒绝。零仍然有效。终端组保留其哨兵误差值（`FLT_MAX`）；其终端标志独立于误差值强制要求精细选择。校验在解码或 GPU 分配之前进行，使 CPU 和 GPU 选择不会对无效非终端误差产生分歧。

每个组的页面引用切片必须包含拥有该组 `groupId` 的簇所在的每一个页面。仅检查切片边界和范围内页面 ID 是不够的：空列表或指向无关驻留页面的引用绝不能使未拉取的精细几何体看起来已驻留。元数据校验在一个集合中收集每个组的簇所属页面 ID，然后移除被其有界引用切片覆盖的 ID。临时成员存储受簇归属记录数量限制，而不受可能重叠的引用切片限制。若有剩余页面未覆盖，会以 `MLOD_INVALID_HIERARCHY`、被遗漏页面 ID 以及该组的页面引用字段偏移显式失败。此检查对完整文件和粗糙引导段在任何页面解码或 GPU 分配之前执行，且不拉取精细页面正文。

目录和元数据跨度在执行 CRC 扫描或读取记录之前必须同时适配已提供的字节和声明的粗糙引导范围。仅 page-data 节可以超出引导范围延伸到文件中未拉取的其余部分。元数据条目不能伪装成页面数据来绕过这些边界。解码后的页面分配必须为正、不大于 256 KiB，并且能被 4 整除以适应 WebGPU 上传。解码器独立强制执行相同的对齐要求。解码后的顶点偏移必须是 4 的倍数，解码后的索引偏移必须是 2 的倍数。元数据在拉取精细页面或分配竞技场（arena）之前以 `MLOD_INVALID_LAYOUT` 拒绝未对齐偏移；直接调用解码器会在分配或调用编解码器前以 `MLOD_PAGE_INTEGRITY` 重新检查它们。非空层级必须包含至少一个终端组；每个终端/固定组的引用页面和每个粗糙页面必须属于固定前缀，从而在加载器报告 `ready` 之前确保存在完整的驻留回退。一个记录最后未固定引用的前缀表以常数时间校验每个回退切片（包括重叠切片），无需反复扫描。

延迟场景构建事务性地暂存数据包。如果任何后续批次失败，所有已暂存的数据包都会被销毁，并恢复其先前的包/可渲染对象标记，因此重试不会孤立缓冲区或已获取的纹理引用。如果延迟构建拒绝，它会在场景队列中重新武装恰好一个特性自有的构建器。修复后的 `registerScene`/`buildScene` 调用会正常排空该工作；成功的批次不会重复附加，已销毁的场景不会重新武装异步工作。

一个输出文件包含一个图元层级。多图元转换会为每个输出赋予确定性的 `.meshNNN.primNNN.mlod` 后缀，使每个图元保留自身的材质和变换。

## 7. 范围加载与粗糙引导

`mesh-lod-range-source.ts` 首先请求字节 `0-65535`，随后最多执行一次延续请求以覆盖声明的引导范围。它在 `206` 响应上校验 `Content-Range`、正文长度、文件大小以及恒等编码；完整的 `200` 响应会被保留而非重复下载。内存数据源直接进行切片。`mesh-lod-runtime.ts` 在 `loadMeshLoD` 解析完成前解析全部元数据并解码/上传固定粗糙页面。损坏的引导或不足的固定页面预算会拒绝该资产；不可用的精细页面不会丢弃其粗糙表面。后续精细页面请求使用同一个字节范围数据源。

## 8. 场景集成

`mesh-lod-scene.ts` 安装单个延迟场景构建器，并按资产/材质标识注册批次。更新期间读取实例世界矩阵、可见性和逐实例误差覆写。构建器在构造由材质拥有的可渲染对象之前校验受支持的 PBR 子集。渲染 MeshLoD 不需要普通的源 glTF 网格；示例加载 GLB 仅是为了复用其 PBR 材质和节点变换。

## 9. 诊断与验证

诊断信息暴露源/渲染三角形数、已选 meshlet 数、可见组数、最大已选/未满足误差、页面需求与驻留状态、已下载字节数、缓存使用量以及选择模式。集成测试对照 GPU 选择、流式传输、生命周期和间接绘制行为验证 CPU 参照实现。示例工作流测试检查启动、控件和源资产加载，而不修改参考截图。示例 GPU 计时使用来自 `getRenderTaskGpuTimings` 的非累加 `totalDurationMs`。

## 10. 选择模型

### 10.1 屏幕空间投影

`mesh-lod-selection-math.ts` 在 CPU 参照实现和 GPU 模型中使用 `Math.fround` 镜像对比较敏感的操作。对于透视相机，像素缩放为 `viewportHeight * abs(projection[5]) / 2`，舍入为 float32 并原封不动地通过共享相机/选择契约传递给 CPU 选择、GPU 模型和选择 UBO。投影在渲染目标按视口调整后的纵横比下解析，因此 XR 使用其注入的逐眼投影而非参考性的相机 `fov`。对于对称透视，这等于 `viewportHeight / (2 * tan(verticalFov / 2))`；没有投影衍生缩放的直接参照夹具保留该 FOV 公式。几何误差乘以实例缩放，再除以相机到包围球表面的距离（受近平面钳制）。共享缩放上界为 `sqrt(max row sum(abs(A^T A)))` 向上舍入至 float32，其中 `A` 是世界变换的线性部分。即使对于存在切变的变换它也能界定算子范数，且对于正交基则退化为最大轴缩放。GPU 在实例记录中缓存此上界，并通过受版本门控的实例上传刷新它。正交相机则使用其可见高度。球/视锥剔除和安全的法线锥剔除会剔除不可见的工作。迟滞机制在误差阈值附近保持先前的精细需求状态。

层级结构利用组依赖关系和页面驻留状态来选择完整切面：仅当所需的更精细几何体可用时，子节点才替换其父节点。流式传输期间选择绝不会暴露空洞。`mesh-lod-selection-cpu.ts` 是参考实现；`mesh-lod-selection-gpu.ts` 打包相同的元数据并在设备上求值。

## 11. 流式调度器与缓存

### 11.1 页面需求

可见组利用相对于传输体积的屏幕空间收益来累积缺失页面需求。调度器按降序优先级排序（相同时按页面 ID 打破平局），而不是拉取每一个缺失页面。需求存在与否独立于优先级：处于下迟滞带中的精细需求组即使其质量压力优先级为零，仍会续订其缺失页面请求。GPU 控制回读携带一个独立的逐页面需求位集，以及收益累加器和已选页面使用标志。每个收益字将其非负 float32 总和存储为 u32 位模式，并通过原子比较/交换循环更新。加法在最大有限 float32 处饱和，而不是在定点 u32 中溢出并将高需求页面回绕为零。回读将浮点数解码并除以存储字节数；CPU 参照实现和确定性 GPU 模型共享 float32 收益数学及与着色器操作顺序一致的饱和累加。CPU 选择器也返回其未归一化的逐页面收益映射表。CPU 渲染绑定以相同的有限 float32 饱和规则将所有需求实例的收益相加，然后将每个总和除以该页面的存储字节数。仅在随后跨不同渲染绑定合并时才取最大值；在同一绑定内共享缺失页面在 CPU 和 GPU 选择中必须以同等程度提高其请求优先级。

### 11.2 请求调度

`mesh-lod-scheduler.ts` 按页面对请求去重、限制并发数（默认为 4），并在两帧宽限期后取消过时工作。无论场景/材质批次、渲染绑定或 GPU 回读数量有多少，每个渲染引擎帧对每个资产贡献一份合并后的需求快照。逐页面优先级取所有活动绑定中的最大值；页面 ID 顺序打破平局。异步 GPU 回读更新其绑定的最新快照，并可在已提交的帧索引处刷新调度，但绝不推进资产时钟。当回读处于待处理状态时，仍在渲染的批次保留上一次成功的快照；显式的空结果会清除它。没有贡献批次的帧提交空需求，直到未完成请求老化淘汰；已移除的批次绝不会续订陈旧快照。只有 _晚于_ 最后需求帧的帧才可计入过时计数：零宽限保留当前帧的需求，并在下一个无需求帧取消它。正宽限保留其现有截止规则。瞬态网络/408/429/5xx 失败最多获得两次重试，延迟分别为 250 ms 和 1,000 ms；协议、完整性和其他永久性错误对该精细页面保持为终结错误。中止与代数令牌可防止过期完成回调修改已销毁或被取代的资产。暂停流式传输会停止新的精细请求，而不停止渲染。

### 11.3 页面状态

固定页面初始即为 GPU 驻留。精细页面依次经历 `unrequested`、`queued`、`fetching`、`received`、`decoding`、`cpu-resident`、`uploading` 和 `gpu-resident`；重试、驱逐和终结失败状态均有显式定义。调度器拥有传输与重试；资产运行时拥有解码与驻留提交。

### 11.4 GPU 竞技场（Arena）

不可变分配的默认容量与预算为 128 MiB。经过设备限制钳制和块取整后，有效设置与诊断信息使用实际的竞技场容量；有效驻留预算上限为该容量。公共预算 setter 拒绝高于已分配竞技场的值，而非最初请求的容量。替换设备恢复在返回前会同时使有效设置与诊断信息与新竞技场对齐。解码后的页面数据占用按 64 KiB 取整的槽位。每个页面必须声明大于零且不大于 256 KiB 的解码分配。即使精细页面字节尚未拉取，元数据校验也会拒绝更大的声明，且解码器在分配暂存内存或调用编解码器前会重新检查该上限。固定粗糙页面不可被驱逐。精细页面在 120 帧保留期后遵循年龄/优先级驱逐，但正在被在途帧引用的页面不可被回收。保护在录制 GPU 选择期间（消费页面状态缓冲区之前）获取，并在该次提交的围栏之后释放；它不更新页面的最后使用帧。仅由已完成的 GPU 通道实际选中的页面才会使用源帧而非回读完成时间来更新 LRU 年龄。在预算降低或来自被需求替换项的分配压力下，仍被先前 GPU 提交引用的冷页面可被标记为 evicting（驱逐中）：未来选择会排除它，但其分配仅在最后一个在途引用排空后才被回收。替换压力退役同时考虑取整后的字节预算以及在现有退役中页面排空后的预期连续空间。它仅退役足够数量的符合条件冷受害者，保留固定、年轻及当前帧选中的页面。随后当其他提交仍在途时，需求即可提交替换；无需队列空闲间隔。容量和有效预算不能小于固定分配量。

### 11.5 CPU 页面缓存

编码字节缓存默认为 64 MiB；固定字节会一直保留以供设备恢复使用。精细缓存字节可独立于 GPU 页面驻留进行驱逐。解码后的暂存字节不会无限期持有。

## 12. GPU 数据与通道

### 12.1 持久布局

设备存储 8 字层级节点、16 字组和簇记录、组到页面引用、8 字页面状态记录，以及不可变的打包几何体竞技场。128 字节的实例记录包含世界变换和法线变换、缩放、标志和稳定实例 ID。这些类型化布局由 `mesh-lod-selection-gpu.ts` 打包。两条渲染路径使用相同的实例打包器。着色法线使用伴随矩阵（cofactor matrix）乘以行列式符号，随后在 WGSL 中归一化。法线锥轴使用相同的逆转置朝向：它们描述的是已创作的外部朝向，而非反射三角形未经修正的绕序。非有限或奇异的世界矩阵会以 `MLOD_INVALID_OPTION` 拒绝，而非产生未定义的光照。该符号位占用法线列填充字 23。MLOD v1 保留 glTF 的右手系、逆时针局部三角形顺序。在 Lite 的左手系相机约定中，其普通 RH 到 LH 实例具有负行列式且无需交换索引。CPU 展开与 GPU `expandClusters` 均通过交换每个三角形的角点 1 和 2 将正行列式实例规范化为批次的 CCW 光栅化器约定。CPU 路径和确定性 GPU 模型共享 `meshLoDTriangleIndex(index, handedness)`；WGSL 使用相同的角点置换和打包符号。每次更新使用当前世界变换，因此运行时的反射变化无需重建批次或拆分其间接绘制即可改变绕序。这也为双面法线修正保留了片元着色器的 `front_facing` 分类。两条选择路径上的法线锥拒绝都必须遵循该规范化后的外部朝向。

### 12.2 逐绑定资源

选择工作队列、组位集、已选簇对、页面需求字、展开后的绘制顶点以及 16 字节间接绘制参数均为瞬态资源。当绘制缓冲区增长时，渲染器以先建后断（make-before-break）方式重建存储绑定。选择前，绘制缓冲区为当前可见实例保留驻留簇顶点数之和，上限为设备的存储缓冲区限制。此包络包含互斥的 LOD，但仅超出该包络并不报错：选中的切面仍可能适配设备。选择会对照绘制容量检查实际切面；如果放不下，整个绘制会被抑制而非绘制部分切面，并在 GPU 回读后上报设备限制错误。在 GPU 模式下，材质数据包仅为其未使用的 CPU 绘制流保留一个最小占位符；GPU 选择拥有实际的绘制缓冲区。
已选对追加列表独立于实例和组状态缓冲区进行界定。设 `L = min(maxStorageBufferBindingSize, maxBufferSize)`，其对容量为 `max(1, min(clusterCount * instanceCapacity, floor((L - 4) / 8)))`：一个 4 字节头后接 8 字节 `(cluster, instance)` 记录。最终字节大小仍接受设备限制校验。隐藏实例、未使用的几何预留槽、非驻留几何体以及互斥 LOD 可能会增加潜在对数量，但不会使适配切面无效。受限后的容量会上传至选择参数。仅当实际追加发生溢出时，才会抑制整个展开/绘制并通过现有的异步回读上报 `MLOD_DEVICE_LIMIT`；绝不绘制溢出切面的任何前缀。GPU 实例预留与瞬态组状态行共享同一容量。对于 `G` 个组，每个预留槽在独立绑定中消耗 128 个实例字节、`max(1, ceil(G / 32)) * 4` 个打包迟滞字节，以及 `G * 4` 个未打包组状态字节。几何增长上限为 `floor(L / max(128, max(1, ceil(G / 32)) * 4, G * 4))`，从而使每个逐实例绑定适配同一个预留量。在分配或替换实例/先前状态资源前，对照该最大值校验所需计数。组状态分配器直接使用此已受限预留量而不再向上取整。这与独立封顶的已选列表不同：适配的实例计数绝不能因为未使用的预留组行溢出而失败。CPU 绘制和实例存储在初始分配和 GPU 到 CPU 切换时同样对照 `maxStorageBufferBindingSize` 和 `maxBufferSize` 中的较小者进行检查。几何增长上限为能适配这些限制的最大完整记录数。在替换任一缓冲区之前预校验两个所需容量；过大的已选切面会抛出包含所需/允许字节数的 `MLOD_DEVICE_LIMIT`，而非分配无效绑定。合法增长会一并发布替换缓冲区、暂存缓冲和绑定组，随后在帧围栏后退役旧缓冲区。每个渲染绑定拥有独立的选择参数、迟滞和绘制缓冲区，包括在单次提交前录制的两个立体眼绑定。不可变资产元数据和材质资源保持共享。CPU 迟滞存放在每个绑定数据包中，绝不放在场景批次注册表中。其 `cpuHistory` 映射以稳定实例 ID 为键，存储 `{ selectionVersion: number, fineRequired: Uint8Array }`；版本号是实例的移除/重新插入选择版本，默认为零。不匹配的版本或组数从零开始；已移除的 ID 在下一次绑定更新（包括空批次）时清理。重新绑定存活目标会复用该历史；新建或已退役/替换的绑定则独立启动。GPU 迟滞保留其现有的逐绑定状态。CPU 流式观察同样按绑定数据包键控，因此一个相机的空/粗糙选择不会覆盖另一个相机的精细需求。帧协调器在每次提交时合并这些活动观察一次。渲染任务的稳定目标签名标识键控这些资源；重新绑定该目标会复用它们，而不分配或使渲染包失效。每个数据包向目标的 MeshLoD 更新批次注册清理函数。任务退役在现有 GPU 围栏后释放数据包并移除其强引用，而不销毁共享材质或资产资源。数据包销毁清除其 CPU 历史并删除其 CPU/GPU 流式观察，同时不干扰其他存活绑定。当槽位移动时，迟滞行跟随稳定实例标识：保留行会被复制到零初始化的替换缓冲中，绝不原地重叠拷贝。移除/重新注册版本会重置复用的标识，即使移除与插入发生在两次上传之间且未增长缓冲区也是如此。

### 12.3 计算顺序

特性自有的 `MeshLoDUpdateBatch` 接入渲染器批次收集机制。每帧中，它清除暂存缓冲区；遍历可见层级节点；评估组误差/驻留状态；选择簇；准备间接派发；然后将选定三角形展开为绘制顶点记录并发布 `drawIndirect` 参数。选择与展开安排在不透明渲染通道之前的两个计算通道中。对页面需求、页面使用位集和计数器的异步回读驱动后续流式传输、实际页面使用老化和诊断信息，而不阻塞当前绘制。回读完成是对源选择结果的观察，不构成额外的渲染帧。回读仅复制控制头、每页一个收益字以及两个 `ceil(pageCount / 32)` 位集，独立于已选列表容量。已选页面使用位集位于缺失页面需求位集之前；`Params.execution.z` 和 `.w` 包含它们的字偏移。即使某页面的累积收益为零，其需求位也保持置位。无视觉 `mesh-lod-demand.spec.ts` 管道测试运行生产 WGSL 和回读解码器，将待处理的细化请求从 2.4 移至 1.9 px，并验证只有真正撤回的需求才会取消请求。它还汇总来自多个填满视口实例的共享缺失页面需求（包括在 1024x1024 目标上 2 px 阈值下的 18 px 误差），并将正的累积优先级与打包缓冲区 GPU 模型对比。同一探针测试还对比实际的 CPU 绑定需求。其浏览器模块 URL 在 Windows 和 POSIX 上均使用规范的 `/@fs/` 路径：多余的斜杠会创建不同的 ES 模块 URL，绝不能将注入的解码器与加载器单例割裂开。该探针验证加载器确实调用了注入的解码器。已选列表带有一个计数头。间接展开根据 `maxComputeWorkgroupsPerDimension` 使用有界 XYZ 维度；着色器将工作组 ID 展平并跳过超出计数的填充。直接选择内核使用相同的多维展平。绝不会为了适配 X 维度而截断任何有效切面。

## 13. 材质拥有的绘制

### 13.1 着色器

PBR 模块组合了一个读取竞技场、展开绘制顶点和逐实例变换的顶点变体。其片元变体使用受支持的 PBR/unlit 材质属性。当存在场景环境时，漫反射辐照度使用其球谐函数，镜面 IBL 使用普通 PBR 材质的粗糙度、地平线遮挡和能量守恒数学采样预过滤环境立方体贴图和 BRDF LUT。没有场景环境时，仅直接光照参与贡献。调试颜色不影响选择或页面驻留。GPU 展开从组元数据、页面状态和法线锥裕度填充诊断属性。`setMeshLoDDebugView` 在默认 GPU 模式下无需切换选择模式即可工作；CPU 路径使用相同的属性含义。受光照和无光照变体共享普通 PBR 输出处理：实时曝光、启用的场景色调映射算法、显示 Gamma，然后是对比度。当启用、禁用色调映射或其算法变更时，绑定在绘制前刷新其着色器/管线键；曝光/对比度保持为实时场景 UBO 值，无需重建着色器。在场景注册前通过 `setFog` 配置的雾会动态导入普通 PBR 雾辅助函数/混合逻辑。雾的存在与否参与着色器键。受光照和无光照颜色在色调映射前混合线性化的雾颜色和雾因子；场景 UBO 提供实时雾模式/参数。在构建完无雾数据包后再引入雾会以 `MLOD_INVALID_OPTION` 拒绝，而不是静默以无雾渲染；请与普通 PBR 一样在注册前配置雾。半球光与其他光源仅在漫反射求值上存在差异；两者都使用共享光照结果的方向、衰减和未混合镜面颜色贡献 GGX 镜面反射。金属-粗糙度将粗糙度钳制到 `[0, 1]`，不设光滑材质下限。普通 PBR 和 MeshLoD 共享 BRDF 与 alpha-G/AA WGSL：基础 `alphaG = roughness * roughness + 0.0005`。当 `enableSpecularAA` 为 true 时，法线导数给出 `slopeSquare = max(dot(dpdx(N), dpdx(N)), dot(dpdy(N), dpdy(N)))`、`AA_factor_x = pow(saturate(slopeSquare), 0.333)` 以及 `AA_factor_y = sqrt(slopeSquare) * 0.75`。IBL 将 `AA_factor_y` 加到 alpha-G 上；直接光源则对 `max(roughness, AA_factor_x)` 求平方并加上 `0.0005`。AA 标志参与每个目标的着色器/管线键，包括现有绑定上的变更。

### 13.2 绑定组

`rebuildMaterial(scene, material, options)` 通过可选的场景材质重建钩子到达 MeshLoD；通用重建路径不包含任何 MeshLoD 导入或语义。该钩子共享调用方的材质/视图匹配，并在特性注册表中串行化重建。它事务性地构建每个匹配的存活批次，保留无关可渲染对象，并仅在成功时发布数据包与可渲染对象替换。即使没有 `rebuildFrameGraph`，场景可渲染对象/材质 epoch 也会使任务绑定失效；该选项会在所有材质工作完成后重建帧图。失败的替换会回滚而不丢弃旧绘制。旧数据包/纹理租约在其提交围栏后退役。异步构建期间发生的场景销毁会丢弃候选项。纹理替换和 `doubleSided` 等结构标志需要此重建；仅 UBO 的编辑继续使用 `markMaterialUboDirty`。

场景绑定占用 group 0。材质的 group 1 绑定其 UBO、四对可选纹理/采样器以及三个存储缓冲区（竞技场、绘制顶点、实例）；缺失的纹理使用材质回退纹理。带光照的环境变体还在绑定点 12–15 绑定场景 BRDF LUT/采样器和预过滤立方体贴图/采样器。材质 UBO 及其可复用的打包临时存储跨目标数据包共享。更新观察 `material._uboVersion`，因此 `markMaterialUboDirty` 在保留当前调试选择器的同时每次变更仅刷新一次受支持的标量/向量属性。四个材质纹理绑定在共享批次构建时捕获。它获取一次应用程序提供的纹理，独立于使用同一材质的普通 PBR 场景。目标数据包和缓冲区增长导致的绑定组重建会复用这些已捕获的绑定，而无需获取额外引用。回退纹理仍归按设备键控的回退缓存所有。共享批次销毁在引擎的 GPU 退役围栏之后精确释放一次已捕获的纹理引用和材质 UBO。延迟场景构建器在分配任何数据包之前校验每个活动批次，因此后续批次中不支持的材质变更不会使较早批次获取的纹理引用发生泄漏滞留。

### 13.3 管线

管线为带有特定目标深度和多重采样数的不透明三角形列表。正面为 CCW；背面剔除遵循 `doubleSided`。法线贴图材质使用普通 PBR 的尺度不变余切帧（cotangent frame）：`det = max(dot(T, T), dot(B, B))` 且 `invmax = select(inverseSqrt(det), 0, det == 0)`。不得有任何加法 epsilon 相对于几何法线衰减切线列。退化的 UV 帧具有零切线列；否则归一化独立于世界缩放、投影和视口尺寸。生产着色器浮点回读在多种投影尺寸和零 UV 用例下对比普通 PBR 和 MeshLoD。

### 13.4 间接绘制

每个资产/材质批次使用一次 `drawIndirect`，无论选中的 meshlet 数量是多少；空批次或已销毁批次不发出绘制。不透明渲染包缓存解析后的绑定组和间接缓冲区。任一资源的变更（包括 CPU/GPU 选择模式切换与缓冲区增长）都会在下一次绘制前使缓存的渲染包失效。

## 14. 资源生命周期

GPU 实例/先前状态容量受 `maxStorageBufferBindingSize` 和 `maxBufferSize` 下的完整记录数限制。符合条件的增长会将几何级数预留量封顶到该限制；超限需求会在替换前失败。瞬态组状态/已选列表增长使用已受限的容量，先校验所有必需缓冲区大小，再一并发布替换。

每个预留的 GPU 回读属于其帧编码器。帧作用域的提交后钩子仅在成功提交后才映射它；刷新前的取消或重置会立即归还槽位。刷新后的重置绝不能释放映射仍在等待的槽位。中止的帧绝不会耗尽环形缓冲。

### 14.1 帧引用

帧引用保护正在使用的页面。CPU 选择持有已选页面；GPU 选择临时持有所有声明为驻留的页面，直到回读识别出已选子集，同时不刷新未使用页面的 LRU 年龄。持有计数与缓冲区替换仅在已提交帧排空后退役。恢复与销毁使延迟回读失效。

### 14.2 销毁

销毁会释放范围数据源的完整文件后备存储，并立即将 `runtime.coarseBytes` 替换为空数组，包括仍存活的场景注册表所持有的 HTTP 200 回退数据。范围数据源会以 `MLOD_DISPOSED` 拒绝后续读取，且无法从延迟响应恢复后备字节。公共元数据与已传输字节诊断信息仍可用。

销毁中止未完成的工作并清除绘制状态。一旦销毁，资产便不能再被渲染。

### 14.3 设备恢复

可渲染对象重建 thunk 在新设备上重新创建材质数据包和 GPU 选择状态。保留的固定字节被重新解码/上传；精细页面可按需重新流式加载。缺失的固定页面会显式导致恢复失败，而不是显示不完整的粗糙几何体。每次成功重建都会将批次的 `renderable` 标记与其结果同步，包括在空批次返回 `null` 且恢复将该批次从场景可渲染对象中省略时将其清除。注册后，添加实例需要具有存活可渲染对象的现有批次。重新激活在恢复期间被丢弃的批次会在修改其实例或注册延迟工作之前以 `MLOD_INVALID_OPTION` 拒绝；一次性场景构建器不会重放。仍拥有存活可渲染对象的空批次可以再次接受实例。恢复会在销毁上一代传出数据包之前先获取替换数据包的纹理租约，包括持久目标复用其更新批次的情况。传出销毁会注销其目标销毁器、清除 CPU 临时缓冲与迟滞，并独立于任务销毁释放 GPU 选择/实例状态。数据包纹理租约捕获其获取的 GPU 分配：在恢复就地修改 `Texture2D` 包装器后，延迟释放绝不能递减或销毁替换分配。仅当该包装器仍标识那个传出分配时，释放通知才生效。重复的绑定目标恢复测试覆盖两种选择模式、稳定的销毁器计数、已释放的临时缓冲/资源以及贯穿最终销毁的替换纹理所有权。

## 15. 示例

### 15.1 附属文件打包

`lab/lite/src/demos/mesh-lod.ts` 使用三个签入仓库的 `.mlod` 附属文件。生产示例输出将这些页面保留在其脚本旁边；实验室通过支持字节范围请求的 `/mesh-lod/` 路由提供它们。

### 15.2 材质与变换来源

该示例从 [BabylonJS Assets](https://assets.babylonjs.com/meshes/harvard-yenching/harvard-yenching_institute_statue.glb) 拉取原始雕像 GLB，仅用于获取材质和节点变换数据。源 GLB 不存储在本仓库中，也不复制到独立示例打包产物中。

### 15.3 示例控件

检查器可调整选择误差、GPU 预算、网络带宽/延迟、暂停以及附带的调试视图。其网络模拟仅包装 `.mlod` 请求（初始为 8 MiB/s 和 100 ms），不包装远程 GLB。缓存预算滑块按资产设置，并使用已加载资产报告的最小不可变容量作为其最大值：随附雕像的默认竞技场允许 32–128 MiB，而非 256 MiB。其初始值来自当前预算诊断信息。滑块标签仅在 setter 成功后更新；被拒绝的修改保留上次接受的标签并恢复滑块拇指位置，同时显示校验错误。诊断面板汇总三个资产的预算，因此每资产 128 MiB 在那里显示为 384 MiB。正常相机支持交互；`?pathTime=` 为工作流验证采样确定性冻结姿势。源模型署名 CC BY 4.0，作者为 Alexandre Tokovinine。

## 16. 自动化回归覆盖

PR CI 在运行单元测试的同时运行基于 Node 托管的 `lite-integration` Vitest 项目，因此在无需本地视觉或性能测试的情况下即可通过加载器、流式传输、共享生命周期、恢复与渲染等价性回归来把关变更。有界元数据变异测试会在尝试对无效跨度进行校验和扫描时中止。普通 PBR/MeshLoD 共享纹理测试覆盖两种选择模式、目标退役、实例缓冲区增长以及受围栏保护的幂等批次销毁。注册/构建门控覆盖公共光照贴图和电介质反射率 setter，以及两种模式下的平移相机浮动原点配置。恢复测试排空初始构建器、移除最后一个实例、执行恢复，并验证两种选择模式下重新激活都会在不改变注册表的情况下被拒绝。存活的已恢复批次保留其移除/重新添加行为。仅 Alpha 拒绝覆盖两种选择模式下的注册、延迟构建和脏更新中省略与 false 混合标志的情况。静态实例 SSE 覆写按 float32 比较，与缓存/上传表示一致；非精确值如 `0.1` 不会触发重复上传，而更改和移除仍会触发。非视觉 GPU 管道回归测试在同一个打包三角形上对比实际普通 PBR 与存储读取 MeshLoD 着色器的浮点回读，涵盖仅半球光金属光照、零/低于 0.045 粗糙度以及开启/关闭 AA 时的变化法线。同一 PR 门控测试规范还在单个批次内以相反行列式符号、重复运行时符号切换、正反视角、启用/禁用锥体剔除以及受光照双面正面修正演练实际的 CPU/GPU 选择、展开与间接光栅化。浮点回读要求两个外部朝向均能渲染，且两个背面保持相应的剔除/光照；每个非空批次始终保持一次间接绘制。模板写入/测试回归显式启用普通材质模板，并在两种选择模式的注册、延迟构建和脏更新中要求返回 `MLOD_UNSUPPORTED_MATERIAL`，不产生场景变更或 GPU 分配/上传。单元测试覆盖也拒绝默认/空的模板对象。逐材质环境回归启用局部立方体贴图，并使用公共覆写、盒/球投影和探针集 setter。两种选择模式均会拒绝注册、延迟构建（包括包含较早有效批次的情况）和脏更新，不产生场景变更或新的材质/绘制资源。清除赋值后仍能使用全局环境正常构建和绘制。仅 MeshLoD 构建回归还要求局部立方体贴图渲染器保持缺失。示例工作流验证缓存滑块的上下限、超出宣称最大值时的钳制，以及标签与聚合有效预算之间的一致性。强制超容量输入验证拒绝操作会保持已接受值完好并报告错误；随后的有效输入会清除该错误。CPU 存储回归覆盖两种设备限制、有界增长、初始分配以及 GPU 到 CPU 切换，包括不替换资源的被拒绝切面。GPU 已选对回归使用随附的 2,491 簇雕像，注册 4,097 个实例（8,192 个预留槽），仅 1 个可见，并设 128 MiB 限制。每个存储限制单独演练。潜在的 163,250,180 字节列表被封顶为限制内的完整记录，选择阶段接收该精确容量，且真实层级的驻留固定切面适配成功。已选列表溢出和绘制顶点溢出仍会上报设备限制错误。同一套完整队列/更新/计算/绘制回归还注册了 65,537 个 312 组雕像实例（仅 1 个可见）。在 128 MiB 下，所需的组状态行占用 81,790,176 字节；公共预留封顶于 107,546 个槽位，而非无效的 131,072 槽位 2 的幂。两个设备限制分别独立演练，所有存储分配和活动行清除均适配成功，实际实例数原样上传，且记录一次间接绘制。直接增长测试包含超过 32 个组的层级，并验证在替换任何资源前拒绝无法适配的所需计数。注入 XR 投影回归要求两个选择器都使用实际垂直缩放、在细化/页面需求上达成一致，并逐眼上传相同缩放。层级克隆测试保留 MeshLoD 状态、独立的 TRS/原始矩阵存储、新 ID 以及独立注册/绘制。双相机 CPU 回归在 2.4/1.5 px 处建立相反的细化历史，随后在默认 2 px / 0.15 迟滞下反复将两者保持在 1.9 px。两种通道顺序均保留各自相机的历史与精细页面需求（包括零取消宽限的零优先级需求）。重新绑定保留历史；中间无更新的移除/重新插入会重置历史，而绑定退役仅在其任务围栏后清除已退役数据包的历史/观察。经 CRC 重新封装的页面成员回归拒绝没有页面引用的非空精细组以及被固定页面替换的范围内列表。完整文件和仅粗糙引导均以 `MLOD_INVALID_HIERARCHY` 失败；公共 CPU/GPU 加载在两次引导请求后即拒绝，不执行页面解码或 GPU 上传。
